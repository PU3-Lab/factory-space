# 2026-06-17 operator_guide 플레이어 답변 가독성 보정 계획

## 목적

agent-test에서 복합 질문을 실행했을 때 `final_answer`에 `equipment_*`, `resource_*`, `recipe_*` 같은 내부 ID가 노출되고, 답변이 한 문단으로 길게 출력되어 플레이어 화면에서 읽기 어렵다.

이번 보정은 LLM이 사용하는 프롬프트 규칙을 강화해, 디버그 정보와 플레이어 답변을 분리하는 것을 목표로 한다.

## 변경 범위

- `system_prompt.py`
  - 플레이어 화면용 답변 원칙 추가
  - 내부 ID는 `metadata`, `sources`, debug view에 남기고 `final_answer`에는 자연어 이름을 우선 사용하도록 명시
  - 복합 질문은 번호가 붙은 짧은 구역으로 답하게 유도
  - 실패/정지 질문이 아닌 경우 트러블슈팅 체크리스트를 붙이지 않도록 제한

- `prompt_builder.py`
  - `[OUTPUT_CONTRACT]`에 같은 가독성 규칙을 추가

## 2026-06-17 보정

복합 질문 답변이 `1.`, `2.` 형식으로만 출력되면 NPC 대화보다는 문서/디버그 응답처럼 보일 수 있다.

따라서 짧은 복합 질문은 다음 방향으로 조정한다.

```text
분쇄기는 무엇인지 설명하고, 철괴는 철광석을 제련기에 넣어 만들면 된다고 한 문단으로 자연스럽게 안내한다.
```

번호 목록은 세 개 이상의 질문이 있거나, 점검 순서처럼 구조화가 필요한 경우에만 사용한다.

## 2026-06-17 추가 보정

번호 목록을 줄인 뒤에도 LLM이 `**굵게**`, 괄호 안 영어 표기, 긴 예시 목록을 사용하면 실제 NPC 말풍선처럼 보이지 않는다.

따라서 다음 규칙을 추가한다.

```text
- 인라인 마크다운 강조를 사용하지 않는다.
- 영어 label을 괄호로 덧붙이지 않는다.
- 슬래시로 여러 항목을 나열하거나 중복 예시를 반복하지 않는다.
- 플레이어가 예시를 요구하지 않으면 예시는 하나까지만 든다.
- 단순 장비/자원/레시피 질문은 2~3개의 짧은 한국어 문장으로 답한다.
- 장비의 역할/사용처 질문에서는 입력 재료 목록이나 레시피 이름을 나열하지 않고, 장비 역할과 다음 공정으로 이어지는 흐름만 설명한다.
```

## 완료 기준

- LLM prompt에 플레이어 답변 가독성 규칙이 포함된다.
- `final_answer`는 플레이어에게 바로 보여줄 수 있는 자연어 중심 문장으로 유도된다.
- 내부 ID는 답변 본문이 아니라 metadata/sources/debug에서 확인하는 구조로 유지된다.
- 관련 테스트와 ruff 검사를 통과한다.
