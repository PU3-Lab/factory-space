# operator_guide RAG 업데이트 및 서버 실행 가이드

- 작성일: 2026-07-02
- 최종 확인일: 2026-07-02
- 기준 경로: `C:\factory-space`

이 문서는 `data/game` 폴더의 CSV 파일을 수정한 뒤 PostgreSQL/pgvector의
RAG 문서를 업데이트하고, 실제 LLM 설정을 사용하는 운영 서버를 실행하는
순서를 설명한다.

## 1. 전체 실행 순서

```text
data/game CSV 수정
-> PostgreSQL/pgvector 실행
-> DB migration 적용
-> CSV 문서 변환 및 embedding 생성
-> RAG 문서 insert/update/deactivate
-> 운영 서버 실행
-> agent-test에서 질문 확인
```

`scripts\setup_rag_db.bat`가 PostgreSQL 실행부터 embedding 반영까지 처리한다.
운영 서버 실행 명령만으로는 RAG 데이터베이스가 자동으로 시작되거나
CSV 변경분이 자동 반영되지 않는다.

## 2. 사전 준비

다음 항목을 먼저 확인한다.

- Docker Desktop이 실행 중이어야 한다.
- `backend\.env.prod`에 DB, embedding, LLM 설정이 준비되어 있어야 한다.
- 명령은 Unreal Editor 내부가 아니라 백엔드가 설치된 PC의 CMD 또는
  PowerShell에서 실행한다.
- API 키와 `.env.prod` 내용은 로그나 메신저에 공유하지 않는다.

## 3. RAG 업데이트

### 3.1 CMD

프로젝트 루트에서 다음 명령을 실행한다.

```bat
cd C:\factory-space
scripts\setup_rag_db.bat
```

### 3.2 PowerShell

```powershell
Set-Location C:\factory-space
.\scripts\setup_rag_db.bat
```

이 스크립트는 다음 작업을 순서대로 수행한다.

1. Docker Compose의 PostgreSQL/pgvector 서비스를 시작한다.
2. Alembic migration을 적용한다.
3. 현재 `data/game` CSV를 RAG 문서로 변환한다.
4. 변경된 문서의 embedding을 생성한다.
5. PostgreSQL의 `manual_rag_documents` 테이블을 갱신한다.
6. 저장된 RAG 문서 수를 출력한다.

정상 실행 예시는 다음과 같다.

```text
Ingestion complete.
inserted=31, updated=122, skipped=89, deactivated=6, failed=0
manual_rag_documents=248
[RAG Setup] Done.
```

각 값의 의미는 다음과 같다.

- `inserted`: 새로 추가된 문서 수
- `updated`: CSV 변경으로 다시 저장된 문서 수
- `skipped`: 내용이 같아서 다시 embedding하지 않은 문서 수
- `deactivated`: 현재 CSV에서 사라져 비활성화된 문서 수
- `failed`: 변환 또는 embedding에 실패한 문서 수

`failed=0`이고 마지막에 `[RAG Setup] Done.`이 나오면 정상 완료다.
문서 수는 CSV 내용에 따라 달라질 수 있으므로 반드시 `248`일 필요는 없다.

## 4. 업데이트 상태만 확인

RAG DB가 실행 중인 상태에서 실제 데이터를 수정하지 않고 CSV와 DB의 차이만
확인하려면 다음 명령을 사용한다.

```bat
cd C:\factory-space\backend
uv run --env-file .env.prod python scripts/ingest_manual_rag.py --dry-run
```

다음 결과는 CSV와 DB가 같은 상태라는 뜻이다.

```text
Dry-run complete.
inserted=0, updated=0, skipped=전체 문서 수, deactivated=0, failed=0
```

`inserted`, `updated`, `deactivated` 중 하나가 0보다 크면 현재 CSV와 DB가
다르므로 `scripts\setup_rag_db.bat`를 다시 실행한다.

## 5. 운영 서버 실행

RAG 업데이트가 끝난 뒤 새 CMD 또는 PowerShell 창에서 서버를 실행한다.

### 5.1 CMD

```bat
cd C:\factory-space\backend
uv run --env-file .env.prod python scripts/run_prod_server.py
```

### 5.2 PowerShell

```powershell
Set-Location C:\factory-space\backend
uv run --env-file .env.prod python scripts/run_prod_server.py
```

정상 실행 시 다음 로그가 표시된다.

```text
[Prod Server] Starting production server on 0.0.0.0:18000
INFO: Application startup complete.
INFO: Uvicorn running on http://0.0.0.0:18000
```

로컬 PC의 agent-test 주소는 다음과 같다.

```text
http://127.0.0.1:18000/agent-test
```

Unreal WebSocket 연결 주소는 서버와 같은 PC에서 테스트할 때 다음과 같다.

```text
ws://127.0.0.1:18000/ws/agent
```

Unreal이 다른 PC에서 실행된다면 `127.0.0.1` 대신 백엔드 PC의 내부 IP 주소를
사용해야 한다.

## 6. 통신탑 질문 테스트

agent-test의 요청 입력창에 다음 JSON을 넣고 전송한다.

```json
{
  "type": "agent.request",
  "request_id": "operator-guide-telecom-recipe-001",
  "session_id": "agent-test-session",
  "client_id": "agent-test-console",
  "agent": "operator_guide",
  "payload": {
    "sub_agent": "operator_guide.recipe_explainer",
    "question": "통신탑 어떻게 만들어?"
  },
  "context": {
    "language": "ko",
    "mode": "agent_test",
    "temperature": 1
  }
}
```

현재 CSV 기준으로 다음 근거가 답변에 반영되어야 한다.

- 제작 장비: 합성기
- 필요 재료: 철근 20개
- 필요 재료: 구리선 20개
- 필요 재료: 주석판 20개

응답의 `metadata.currentModel`에서 실제로 답변한 모델을 확인할 수 있다.

## 7. 자주 발생하는 문제

### PostgreSQL 연결 실패

```text
RAG database connection failed.
```

Docker Desktop과 RAG 컨테이너가 실행 중인지 확인하고 다음 명령을 다시 실행한다.

```bat
cd C:\factory-space
scripts\setup_rag_db.bat
```

### CSV를 수정했지만 답변이 바뀌지 않음

CSV 저장만으로 PostgreSQL/pgvector가 자동 갱신되지는 않는다.
`scripts\setup_rag_db.bat`를 다시 실행한 뒤 서버를 재시작한다.

### RAG DB 없이 서버만 실행함

서버는 CSV 근거만으로 fallback 답변을 만들 수 있지만 pgvector 검색은 사용할 수
없다. 실제 RAG 통합 테스트에서는 RAG DB를 먼저 실행한다.

### 모델이 예상과 다름

응답의 다음 필드를 확인한다.

```text
payload.metadata.llmSlot
payload.metadata.llmProvider
payload.metadata.llmModel
payload.metadata.currentModel
```

기본 OpenAI 호출이 실패하면 Gemini, 로컬 모델 순서로 fallback할 수 있다.
모델 오류는 서버 로그에서 `OpenAI LLM call failed`,
`Google Gen AI LLM call failed`, `Local LLM call failed` 문구를 확인한다.
