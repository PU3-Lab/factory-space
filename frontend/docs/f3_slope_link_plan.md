# F3 계획 — 단차 연결: (가) 경사 컨베이어 vs (나) 램프 Foundation 비교

작성일: 2026-06-11 · 선행: F2 종결(`d5582a9`, f2_height_snap_plan.md) · 상태: **확정 — (나) 램프 착수**
(결정점 ㉮~㉵ 전부 추천안 승인, ㉯만 PIE 체감 비교 후 최종 확정 — 미결 태그 유지)

> 배경: F2 높이 스냅으로 Foundation이 N×100uu 단으로 배치되고, 단차 걸침은
> `OJJ_GetUniformSurfaceZ`가 거부(의도 — PIE 확정). 단(段) 사이를 잇는 수단이 없음:
> 캐릭터는 100uu를 못 오르고(MaxStepHeight 45), 컨베이어는 단차 경로가 거부됨
> (OJJ_Grid.cpp:340-347 — "F3(컨베이어 높이 인지)에서 해소" 태그).

## (가) 경사 컨베이어 세그먼트 — 컨베이어가 단차를 직접 오르내림

### 그리드 측(우리 소유) — 작음
- `OJJ_CollectConveyorReservedCells`의 단일면 게이트(:343) 완화: "전 셀 동일 SurfaceZ" →
  "인접 셀 간 SurfaceZ 델타 ≤ 경사 한계(예: 1단 = 100uu를 K셀에 분배)" + 경사 구간 마킹.
- `PathSurfaceZ` 단일값(:2253-2255) → 경로 셀별 Z 배열 전달로 확장.

### 벨트 측(SSR/Chan 소유) — **큼, 그리고 우리 경계 밖**
`AConveyor`(Conveyor.h/.cpp)의 평면 전제가 전 층위에 박혀 있음:
- **경로 표현**: `SetPath(TArray<FIntPoint>, CellSize)` — Z 없는 2D 셀 목록. 셀→로컬 변환도
  수동식(`Cell*CellSize + 0.5*CellSize`, GridToWorld 미경유 — 기존 parity 부채, OJJ_Grid.cpp:2243 태그).
- **세그먼트 비주얼**: Straight/Corner ISM 2종 — 경사 세그먼트(직선 경사 + 경사↔평지 전환 + 코너×경사
  조합) 메시·배치 로직 신규.
- **아이템 이동 보간**: `ItemVisualInstances` — 평면 경로 가정의 보간(Z 고정 `ItemVisualZOffset 28`).
  3D 보간으로 일반화 필요.
- **포트 Z**: 양 끝 머신 포트 높이가 다른 경로 — 입출력 Z 정합 신규 규칙.

### 경계 판단
그리드 측 게이트 완화는 우리가 해도 되지만, **벨트 내부(경로 Z·세그먼트·아이템 보간)는 아이템
흐름 코드와 한 몸 — SSR/Chan 리뷰/협업 필수**. F1-c 때도 벨트는 안 건드리고 그리드 측 앵커
시프트로 우회한 전례(OJJ_Grid.cpp:2243). 단독 진행 불가가 (가)의 실질 비용.

## (나) 램프 Foundation — 경사면 타일을 Foundation 종류로 추가

### 핵심 난제 검증: 셀별 SurfaceZ 표현 — **이미 준비되어 있음 (난제 아님)**
`FOJJFoundationCellInfo`(OJJ_Grid.h:31-47)는 **설계 시점부터 셀별 SurfaceZ 저장**:
> "SurfaceZ는 상면 월드 Z — F1은 footprint 전 셀 동일값이지만 **F2(높이 스냅/경사) 대비 셀별 저장**."

즉 램프 = "셀별로 다른 SurfaceZ를 가진 Foundation" — 자료구조 변경 0. 표현 모델은
**계단 근사**가 정답: 그리드 데이터는 셀당 평탄면(계단), 경사 보간은 메시/충돌의 일.
- 8×8 한 장이 1단(100uu) 오르면 행당 +12.5uu 계단 — **캐릭터 MaxStepHeight 45로 도보 가능**
  (계단 근사조차 걷기 성립 — wedge 충돌 없이도 동작).
- 소비처 자동 정합: `GetFoundationSurfaceZ`는 원래 셀별 조회. 램프 경사 구간에 머신/컨베이어를
  놓으면 `OJJ_GetUniformSurfaceZ`가 이높이로 **자동 거부**(바람직 — 경사 위 배치 금지가 공짜).
  램프 양끝의 평탄 행은 해당 단의 Foundation과 같은 SurfaceZ → 걸침 배치 자동 허용.

### 기존 파이프라인 재사용 범위 — 대부분 재사용
| 단계 | 재사용 | 필요 변경 |
|---|---|---|
| 배치 검증(CanPlaceFoundation) | ✅ 그대로 | 없음(셀 단위 게이트 — 높이 무관) |
| 등록(TryPlaceFoundation) | 구조 재사용 | **셀별 SurfaceZ 오버로드**(현재 단일 float → per-cell 산출 콜백 or 배열) — 중 |
| 스냅(OJJ_ComputeFoundationSnapLift) | ✅ 재사용 | 램프는 "시작단 N" 산정에 그대로 사용, 끝단 = N+1 |
| 호버 표면 게이트 | ✅ 자동 | `IsA<AOJJ_Foundation>` — 파생 클래스 커버 |
| 철거/위 건물 거부/호버 게이트 | ✅ 자동 | Foundation 액터 단위 — 셀별 Z 무관 |
| 올려태우기 | 구조 재사용 | 단일 SurfaceZ → Pawn이 걸친 셀의 SurfaceZ(max) — 소 |
| 비주얼(UpdateSlabVisual) | ❌ 신규 | 큐브 스케일 → **계단 박스 K개 or wedge 메시** — 중 |

### 숨은 비용 (이게 진짜 결정점)
1. **방향성 → Foundation 회전 도입**: 현재 Foundation은 "회전 F1 미지원(정사각 8×8)"
   (BuildController:915). 램프는 오르는 방향이 있어 **회전 4방이 필수** — 호버/배치 origin 변환
   (ComputeOriginFromCursorCellForSize)은 정사각이면 회전 불변이라 작지만, 셀별 SurfaceZ 산정과
   메시 회전이 방향을 타야 함. 머신 회전(HoverRotationSteps) 패턴 재사용 가능 — 중.
2. **메시/충돌 에셋**: 엔진 기본에 wedge 없음. (i) 계단 박스 K개(엔진 큐브 재사용, 에셋 0 — 프로토
   추천) vs (ii) wedge 전용 에셋(에셋 파이프라인 — AGENTS.md commandlet 규칙). (i)로 시작 추천.

### 효과
- **캐릭터 도보 단차 해소** — 지금 100uu 못 오르는 문제의 직접 해결(이건 (가)가 못 줌).
- 단, **컨베이어 단차 연결은 (나)만으로 안 됨**: 램프 셀 위 컨베이어도 이높이 거부(자동 차단의
  반대면). 컨베이어가 단을 넘는 건 후속 — 램프 경로를 따라 인접 셀 델타 12.5uu를 허용하는
  "(가)-lite"(그리드 게이트 완화 + 벨트는 segment별 Z — SSR/Chan 협업)가 자연 후속.

## 결정점 현황 (2026-06-11 전부 확정 — 추천안 일괄 승인 + 보강 3건)

- **㉮ ✅** (나) 램프 Foundation 먼저 — (가)는 램프 규격 확정 후 SSR/Chan 협업 안건으로
- **㉯ ✅(미결 태그)** 8×8 **기본값** + 램프 크기 EditAnywhere — **PIE에서 4×8과 체감 비교 후 확정**
  (행당 계단: 8행 ≈14.3uu / 4행 ≈33.3uu — 둘 다 MaxStepHeight 45 미만)
- **㉰ ✅** 계단 근사(셀별 SurfaceZ + 계단 박스 비주얼) — wedge 메시는 비주얼 폴리시로 이연
- **㉱ ✅** Foundation 회전 4방 도입(머신 HoverRotationSteps 패턴 재사용) — 평판은 회전 불변(회귀 0)
- **㉲ ✅(보강)** 셀별 SurfaceZ 등록 = (i) 셀→Z 배열 전달(`OJJ_TryPlaceFoundationPerCell` —
  TryPlaceFoundation은 UFUNCTION이라 UHT 오버로드 불가, 별도 이름).
  **그리드가 배열 불변식 검증 — 액터 신뢰 금지**: ① 배열 크기 = Size.X×Size.Y(int64 비교)
  ② 전 셀 Z 유한값 ③ (max−min)이 단 간격(100)의 정수배 — *절대* 단 격자 정합(평면+Thickness 기준)은
  그리드가 Thickness를 모르는 F1-b 계약상 **상대 검증**으로 구현, 절대 정합은 양 끝 정합 산식(아래)이
  클래스 측에서 보장. 위반 시 배치 거부 + OutReason(이중 방어 — 산식은 램프 클래스, 검증은 그리드).
- **㉳ ✅** 올려태우기 — Pawn이 걸친 셀들의 SurfaceZ max
- **㉴ ✅** §5-2 은퇴 F4 분리
- **㉵ ✅** 컨베이어 단차((가)-lite) F3 범위 밖 — 램프 규격 확정 후 SSR/Chan 협업 안건 발제

### [보강] 램프 양 끝 정합 산식 — 턱 0 불변식
오르는 방향 행 r = 0..R−1 (R = 방향 길이):

```
SurfaceZ(r) = Z_low + (r / (R−1)) × 100,   Z_low = 평면 + Thickness + N×100
```

- **r=0 (최하단 행): Z_low와 정확 일치** — 낮은 단 평판 Foundation과 같은 면 → 걸침 배치/도보 턱 0.
- **r=R−1 (최상단 행): Z_low + 100 = N+1단 SurfaceZ와 정확 일치** — float도 (R−1)/(R−1)=1이라 오차 0.
- 양 끝 행은 인접 평판과 SurfaceZ 동일 → 기존 OJJ_GetUniformSurfaceZ가 걸침 배치를 **자동 허용**
  (같은 값 비교), 중간 행은 자동 거부 — 추가 규칙 0.
