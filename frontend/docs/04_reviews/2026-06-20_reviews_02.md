# 2026-06-20 코드 리뷰 02 — 파이프-탱크 연결을 탱크 소켓 높이로 라이즈

- **대상**: 다리로 띄워진 LiquidTank의 높은 연결구에 파이프 끝을 맞추는 변경(A 방향 — 소켓 + 파이프 끝 Z 라이즈)
- **리뷰 범위**: `OJJ_Grid.cpp`(`OJJ_TryPlacePipe` 소켓 lift 주입), `Pipe.h`(`GetZOffset` 게터). `SM_LiquidTank.uasset`(JJ 소켓, 바이너리 — 코드리뷰 대상 외)
- **리뷰 방식**: 8앵글 다중 에이전트(정확성 line-by-line/cross-file/RebuildVisuals 역산 + 정리/고도/규약), high effort
- **PIE**: 통과(파이프가 탱크 소켓 높이로 라이즈, XY 무관·Z만 사용 확인 — JJ)
- **빌드**: 통과

## 변경 요약
`OJJ_TryPlacePipe`의 `CellLifts` 산출 직후, 터미널 셀(끝=Target `PipeInlet`, 시작=Source `PipeOutlet`)의 lift를 머신 메시 소켓 월드 Z로 라이즈. 노드 월드Z = `PathSurfaceZ + ZOffset + lift` 관계에서 `lift = SocketWorldZ − PathSurfaceZ − ZOffset` 역산. 인접 셀 lift 차로 `RebuildVisuals`가 지면→소켓 수직 라이저를 자동 생성(기존 F4-3 패턴 재활용), #257 끝 스텁이 그 높이에서 포트로 물림.

## 검증 (전부 PASS)
1. **레퍼런스 프레임**: 파이프 액터가 world Z=`PathSurfaceZ`에 앵커(`:2961`, yaw-only·CentroidLocal.Z=0), 노드 로컬 Z=`ZOffset+lift` → 월드Z=`PathSurfaceZ+ZOffset+lift`. 소켓 **월드** Z 직접 사용 → 공식 정확. 기존 오버패스(F4-3)와 동일 프레임. ✅
2. **인덱스**: index 0=Source, NumPipeCells-1=Target(`PlacementCells.Last()`=탱크 접근 셀, `:2850` 주석 일치). NumPipeCells≥1 보장(`OJJ_ValidatePipePlacement` 빈 경로 거부). ✅
3. **배열 길이**: `CellLifts`는 `NumPipeCells`(=`GetPathCells().Num()`)로 초기화, in-place 변형으로 길이 불변 → `OJJ_SetPathCellLocalZs`의 `==PathCells.Num()` 체크 통과. ✅
4. **가드**: `IsValidIndex` + `IsValid(Machine)` + `MeshComp` null + `DoesSocketExist` → 소켓 없으면(펌프 현행/실린더 폴백/미작업) no-op = 기존 지면 lift 유지(안전). `FMath::Max`로 음수 라이저 방지. ✅
5. **소켓 월드Z + 스케일**: 연결 대상은 이미 배치·`OnConstruction`/`FitMeshToGrid`(SpawnActor 동기) 완료된 머신 → `GetSocketLocation`이 fit-scale·회전 반영한 월드 Z 반환. 레이스 없음. ✅
6. **다른 경로**: `OJJ_TryPlacePipe` 호출처(`OJJ_BuildController` 배치 / `FactorySaveSubsystem` 복원) 모두 동일 로직 경유 → 배치/리로드 일관. ✅
