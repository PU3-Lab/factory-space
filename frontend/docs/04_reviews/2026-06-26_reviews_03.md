# 코드 리뷰 — 공중(허공) Foundation 높이 오프셋

- **일자**: 2026-06-26
- **리뷰어**: Codex (gpt-5.4) 위임 리뷰 + Claude 평가
- **대상**: 공중 Foundation 높이 오프셋(BuildHeightOffset, Q/E TPS + ↑↓ 탑다운, clamp 0~20, (b) 이웃 coplanar, 다리 자동연장 재사용)
- **빌드**: UE 5.7 `Wanted_FactoryEditor` Development 통과

## 변경 요약
- `BuildHeightOffset`(int32) 멤버 + Enter/Exit 0 리셋 + `AdjustBuildHeight`(clamp 0~20, 게이트 빌드모드&&Foundation&&!Ramp).
- `IA_BuildHeight`(Axis1D) — TPS Q/E + 탑다운 ↑↓ 공유, 같은 핸들러/오프셋.
- `GetFoundationHeightLiftZ(CDO,Origin,EffSize)` — 게이트(!IsInBuildMode||Ramp||offset<=0) + (b) 이웃 접촉 시 0(coplanar). 단일 소스를 3곳(스폰/슬래브 고스트/타일 프리뷰)에 전달.
- 다리 자동연장 = `OJJ_Foundation::UpdateLegVisual` 재사용(무변경).

## 이슈 목록

### 🔴 Blocker
없음.

### 🟠 Major

#### M1. 타일 프리뷰 Z 기준이 슬래브/스폰과 다름(셀별 시각표면 vs 평면+SnapLift) → ⚠️ **선존재(pre-existing), 높이기능 결함 아님**
- **위치**: `OJJ_Grid.cpp:3001`(타일=`OJJ_GetCellVisualBaseZ(셀별)+...+HeightLiftZ`) vs `:5145/5159`·`OJJ_BuildController.cpp:1574`(슬래브/스폰=`평면+SnapLift+HeightLiftZ`).
- **내용**: 경사 지형 씨앗 배치 시 타일 프리뷰가 셀별 표면 기준이라 슬래브 평면과 셀별로 어긋날 수 있음.
- **평가**: `HeightLiftZ`는 3경로에 **동일하게** 더해지므로 높이 오프셋은 정합. 어긋남은 **타일=셀별 시각Z / 슬래브=평면Z** 라는 **기존 구조**(높이 기능 도입 전부터 존재) 때문 — 높이 기능이 악화시키지 않음. 평지에선 무증상. f2-terrain-z-backlog(셀-최고점/평면 Z) 영역.
- **조치**: 높이 기능 범위 밖. 타일은 footprint 표시(셀별 표면 기준)임을 인지. 정합이 정말 필요하면 별도 후속(타일도 평면 Z 사용)으로.

### 🟡 Minor

#### m1. 램프/None 전환 시 BuildHeightOffset 잔류 → **설계 선택(현재=세션 기억)**
- **위치**: `OJJ_BuildController.cpp` AdjustBuildHeight 게이트 / SetPlacementMode / OJJ_SelectFoundationKind.
- **내용**: offset은 Enter/Exit에서만 리셋. `Flat 높이 올림→Ramp→None→Flat 재선택` 시 이전 offset 되살아남(램프 중엔 게이트로 미적용, Flat 복귀 시 재적용).
- **평가**: 회전(`HoverRotationSteps`)·Foundation종류와 **동일 라이프사이클**(빌드 세션 내 유지). "세션 기억"이면 정상.
- **조치**: 현재 동작 = 세션 기억으로 확정(헤더 주석 명시). "취소 시 0" UX를 원하면 `SetPlacementMode(None)`/`OJJ_SelectFoundationKind(ramp)`에 `BuildHeightOffset=0` + sentinel 추가 — **사용자 결정 대기**.

#### m2. 헤더 주석이 TPS 중심(구현은 탑다운도 허용) → ✅ **수정 완료**
- BuildHeightOffset/IA_BuildHeight/GetFoundationHeightLiftZ 주석을 "Foundation(Flat) — TPS Q/E + 탑다운 ↑↓"로 정정.

### ⚪ Nit (수정 완료)
- **이중 호출**: UpdateFoundationHover가 `GetFoundationHeightLiftZ`를 타일/슬래브에 2회 호출 → `FoundationHeightLiftZ` 1회 계산 공유(이웃 조회 중복 제거). ✅
- **clamp 하드코딩**: `20` → `constexpr int32 MaxBuildHeightOffset = 20`. ✅

### 이웃 판정 엣지 — 결함 없음 (Codex 확인)
- `GetFoundationHeightLiftZ` 이웃 접촉 시 0 반환 → 스폰 `OJJ_ComputeSnapLift ①상속`이 같은 이웃 SurfaceZ 상속. 공중 씨앗도 등록 SurfaceZ가 `Thickness+N*100` 격자라 `OJJ_AccumulateFoundationSurfaceZ` 필터 통과. coplanar 확장 정합.

## 우선순위 권고
1. **M1(타일 Z)** — 선존재, 높이기능 무관. 평지 무증상. 별도 후속(원하면).
2. **m1(램프/None 리셋)** — 설계 결정 필요(세션 기억 유지 vs 취소 시 0). 현재 세션 기억.
3. Nit/주석 — 수정 완료.

## 긍정적인 부분
- `AdjustBuildHeight` 모드/램프 가드 + sentinel 갱신 적절.
- 스폰에서 `SnappedLocation` 하나에 HeightLiftZ를 더해 ActorZ·BaseSurfaceZ 동시 정합.
- 이웃 접촉 시 직접 더하지 않고 기존 `OJJ_ComputeSnapLift` 상속에 위임 → 중복 높이 적용 회피.
- 다리 자동연장을 기존 UpdateLegVisual 재사용으로 무작업 해결.
