# 2026-06-19 코드 리뷰 01 — 빌드 모드 카메라 플레이어 위치 기준 배치

- **대상 커밋**: `cfff130` (feat: 빌드 모드 카메라 플레이어 위치 기준 배치 + PlayerStart 위치 조정)
- **리뷰 범위**: `Source/Wanted_Factory/Private/OJJ_Player.cpp` — `AOJJ_Player::ApplyBuildModeView` (카메라 코드만). `L_Planet.umap`(PlayerStart, 바이너리)은 리뷰 대상 제외.
- **리뷰어**: Codex (codex:rescue) + Claude 평가

## 변경 요약

빌드 모드(B) 진입 시 탑다운 빌드 카메라를 **그리드 센터 고정** → **플레이어 현재 위치 기준**으로 변경.

```cpp
// OJJ_Player.cpp:716~722 (ApplyBuildModeView, bEntering=true)
if (const AOJJ_Grid* Grid = BuildController->GetTargetGrid())
{
    const FVector PlayerLoc = GetActorLocation();
    const FVector CamLoc(PlayerLoc.X, PlayerLoc.Y, Grid->GetGridCenter().Z);
    BuildCamera->SetActorLocation(CamLoc);
}
```

- XY = 플레이어 현재 위치(`GetActorLocation()`)
- Z = 그리드 평면(`GetGridCenter().Z`) **유지** — 등반 높이에 안 묶임, 탑다운 거리 일정
- 진입 **1회** 배치(추종 아님), SpringArm(pitch −90 / arm 1500) 불변

## 이슈 목록

### 🟠 Major — off-grid 플레이어 XY로 진입 시 커서가 무효 셀에서 시작
- **위치**: `OJJ_Player.cpp:716~720` (`ApplyBuildModeView`)
- **내용**: 카메라 XY를 `GetActorLocation()`에 맞추면, 플레이어가 **타겟 그리드 placement 범위 바깥**에 서서 빌드 진입할 때 카메라가 비-그리드 공간 위로 배치된다. 빌드 커서는 `GetHitResultUnderCursorByChannel`(`OJJ_BuildController.cpp:569`) → `WorldToGrid`(`OJJ_Grid.cpp:910`, 순수 XY) → 유효성 `IsValidGridCell` `[0, GridSize)`(`:1030`) 경로. 레이는 Landscape를 맞히지만 **무효 셀로 매핑**되어, 사용자가 그리드로 패닝해 돌아올 때까지 hover/place가 막히거나 cleared.
- **완화 확인(2차 정독)**: 1차 패스가 우려한 "등반 중 진입"은 `ToggleBuild`가 `ApplyBuildModeView` **전에 `AbortClimb()`를 호출**하고 이 코드가 플레이어 Z를 무시하므로 **대부분 해소**. 남은 실제 리스크는 **off-grid XY 단일 케이스**.
- **영향**: 정상 동선(그리드/Foundation 위에서 B → 수직 하향 조준)에서는 문제 없음. 그리드 밖에서 진입할 때만 발생. Codex·Claude 모두 차단(block) 사유는 아님으로 판단.
- **제안(채택)**: `WorldToGrid(PlayerLoc)`가 `IsValidGridCell` 밖이면 **`GetGridCenter()`로 폴백**(off-grid 안전 복귀), 안이면 플레이어 추종. 정상 동선은 추종 유지, 유일한 실 리스크 제거. 한 줄 수준.

### ✅ OK — Z = 그리드 평면 유지
- **위치**: 동일 함수, `CamLoc`의 Z 성분
- **내용**: `GetGridCenter().Z` 유지는 기존 거동과 일관되고, 카메라 높이를 등반 높이에 묶지 않는다. SpringArm이 런타임 상향 오프셋(arm 1500)을 담당.
- **판단**: 적절. 변경 불필요.

## 우선순위 권고

- **🟠 Major는 지금 폴백 가드 추가 권장**(백로그 아님). 2차 정독으로 리스크가 off-grid XY 단일 케이스로 좁혀졌고, `IsValidGridCell` 폴백이 싸고 리스크 0이라 유일한 실 리스크를 즉시 제거 가능. 정상 동선의 플레이어 추종은 그대로 유지된다.
- PIE 검증 (a) 플레이어 위 탑다운 (b) 가장자리/원거리 (c) 높은 Foundation 위 스케일 일정 (d) 조준 플레이어 주변 (e) 줌/회전/패닝 정상 — 통과 시 마무리.

## 해결 및 최종 검증

- 🟠 Major는 **본 커밋에서 폴백 가드로 해결**: `Grid->IsValidGridCell(Grid->WorldToGrid(PlayerLoc)) ? PlayerLoc : Grid->GetGridCenter()`. 그리드 안 → 플레이어 추종, 밖 → 센터 폴백.
- 폴백 적용 후 증분 빌드 통과(`Result: Succeeded`, 에러 0).
- **Codex 최종 리뷰: 승인(Approved), Findings: None.** 경계 셀(half-open `[0,GridSize)`) 정상, `WorldToGrid`가 Z 무시 확인, 신규 회귀 없음.
- ⚪ Nit(미적용, 무해): `GetGridCenter()` 이중 호출 — 캐싱 시 정리되나 동작 영향 없어 보류.
- 범위 밖(가드 무관, 별도 UX 결정): 진입 후 런타임 팬/줌으로 커서가 off-grid 이동, 빌드 중 동적 GridSize 변경.

## 긍정적인 부분

- 수정 포인트를 단일 지점(`SetActorLocation` 한 줄)으로 한정 — 패닝/회전/줌/조준은 BuildCamera 액터 트랜스폼을 그대로 재사용하므로 자동 반영, 부수 변경 없음.
- Z를 그리드 평면에 고정해 고저차 큰 지형에서 화면 스케일 출렁임을 사전 차단(설계 판단 명확).
- null 가드(BuildCamera/BuildController/Grid)가 기존 블록에 이미 존재.
- 증분 빌드 통과(`Result: Succeeded`), 의도한 2개 파일만 변경(섞인 변경 없음).
