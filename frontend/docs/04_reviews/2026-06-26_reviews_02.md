## 이슈 목록

### 🔴 Blocker (Codex 제기) → ❌ **기각 (오탐, false positive)**
**위치**: `OJJ_Grid.cpp` `OJJ_FindConveyorRoute` 힙 comparator `Cmp = [](A,B){ return A.F < B.F; }`
**Codex 주장**: UE 힙에서 `A.F < B.F`는 max-heap이라 A*가 최고 F부터 확장 → 비효율/오류. `A.F > B.F`로 바꿔라.
**검증 결과 — 기각**:
- UE 5.7 엔진 소스 `Engine/.../Containers/Array.h:3646` — `Heapify`/`HeapPush`/`HeapPop`은 "Assumes < operator is defined", 기본 predicate = `TLess<ElementType>()` = **min-heap**(최소가 top, `HeapPop`이 predicate 기준 **최소** 반환).
- 따라서 `A.F < B.F`(TLess 형태)는 **정상 min-heap** → A*가 **최소 F부터** 확장(정확). 현재 코드 올바름.
- ⚠️ **Codex 제안(`A.F > B.F`)을 적용하면 오히려 진짜 max-heap 버그**가 됨 — 절대 적용 금지.
**조치**: 변경 없음. (이 주석을 코드에 남기는 것 검토 가치 있음 — 후속 오인 방지)

### 🟠 Major 1 — A* 꺾임비용 최적성 (셀-only 상태) → ⚠️ **의도된 v1 단순화 (수용)**
**위치**: `OJJ_Grid.cpp` `OJJ_FindConveyorRoute` — `G`/`Came`/`ArriveDir`가 `FIntPoint`(셀)만 키.
**내용**: 이동비용이 `ArriveDir`(도착 방향)에 의존하지만 상태키에 방향이 없어, 같은 셀을 다른 방향으로 더 싸게 재방문 못함 → turn penalty 하의 **최적 경로 미보장**(불필요한 꺾임 가능).
**평가**:
- **휴리스틱은 admissible**: 맨해튼*StepCost. 실제비용 = 스텝 + 꺾임(≥0 가산)이라 항상 휴리스틱 ≤ 실제 → 과대평가 없음. 즉 **경로를 못 찾는 일/엉뚱한 경로는 없음** — 유효한 경로는 항상 찾음. 다만 꺾임 최소가 아닐 수 있음.
- 사용자 합의 "기본 A* 먼저, 튜닝 여지". **v1 수용 가능**. 비최적은 시각적 품질 문제지 기능 결함 아님.
- 개선안(후속): 상태키를 `(Cell, ArriveDir)`로 분리 → 완전 최적. 비용=상태공간 4배. 필요 시 A* 튜닝 단계에서.
**조치**: 현행 유지(수용), 후속 개선 옵션 기록.

### 🟠 Major 2 — TPS 물 보정 마우스 ray (M2 중복) → ⏳ **기존 후속 (reviews_01 M2)**
**위치**: `ResolveCursorCellOverWater` 내부 `DeprojectMousePositionToWorld`(마우스) — TPS는 화면중앙인데 물 보정만 마우스.
**내용/영향**: reviews_01의 **M2와 동일**. TPS 물/해안 조준 시 셀 튐. TopDown 무영향(회귀 아님).
**조치**: 기존 M2 후속으로 이미 등록됨(메모리/reviews_01). 신규 아님.
