# 2026-06-20 코드 리뷰 01 — 옛 빌드 입력 경로 전수 정리 (직행키 + Group A)

- **대상**: 카테고리 숫자키 슬롯(LDJ `UI_BuildModeMain`)이 완전 대체한 옛 배치모드 진입 경로의 C++ 전수 제거
- **리뷰 범위**: `OJJ_Player.h` / `OJJ_Player.cpp` (입력 바인딩 + 핸들러)
- **방식**: 추측 제거 금지 — 전수 grep 분류 → 범위 합의(전체 제거) → 구현
- **정책**: C++만 제거(UPROPERTY/BindAction/BindKey/핸들러). IA `.uasset`·IMC·BP·enum 미변경.

## 변경 요약

전수 grep 결과 옛 진입 경로는 전부 `OJJ_Player.h`/`.cpp` 두 파일에 국한(외부 C++/BP 참조 0). 다음을 제거:

### 직행키 (레거시 `BindKey`, C++ 하드코딩)
- `EKeys::O` → `SetMoldingMachineModeShortcut` (성형)
- `EKeys::P` → `SetSynthesizerModeShortcut` (합성)
- `EKeys::T` → `SetTeleCommunicationTowerModeShortcut` (통신)

### 직행키 (IMC `BindAction`)
- `IA_SetTankMode` → `SetTankMode` (K, 물탱크)
- `IA_SetPowerLineMode` → `SetPowerLineMode` (−, 전력선)

### Group A 10 + Pipe (IMC `BindAction`)
- `IA_SetMachineMode`/`SetMachineMode` (중앙거점·신호증폭기는 슬롯이 동일 enum 사용)

- `IA_SetPowerNodeMode`/`SetPowerNodeMode`

### 유지 (범위 밖)
- 철거: `IA_SetDemolishMode`/`SetDemolishMode` + `EKeys::X`/`SetDemolishModeShortcut`
- 공용키: F/G(Foundation·Ramp), H(Ladder), Z(Cancel), 숫자키 슬롯 1~0

## ⭐ #308 (튜토리얼 이벤트 정합) 검증 — 안전

퀘스트 리스너(`QuestManagerSubsystem.cpp`)가 실제 요구하는 이벤트 7종은 전부 슬롯 경로
(`UI_BuildModeMain::ExecutePlacementMode` → `Printf("Select%sMode", SubsystemKey)`)가 발사하며,
해당 머신은 전부 카테고리 숫자키 슬롯으로 커버됨. 삭제된 핸들러가 쏘던 문자열은:

| 핸들러 발사 | 슬롯 발사(리스너 청취) | 판정 |
|---|---|---|
| `SelectConveyorMode` | `SelectConveyorMode` | 동일 ✅ |
| `SelectPowerPlantMode` | `SelectPowerPlantMode` | 동일 ✅ |
| `SelectSmelterMode` | `SelectSmelterMode` | 동일 ✅ |
| `SelectWarehouseMode` | `SelectWarehouseMode` | 동일 ✅ |
| `SelectPowerLineMode` | `SelectPowerLineMode` | 동일 ✅ |
| `SelectPowerNodeMode` (옛) | `SelectPowerGridNodeMode` | 이미 고아(#306에서 리스너 이전) — 무해 ✅ |
| `SelectMinerMode` (옛) | `SelectMinerMachineMode` | 이미 고아(#306에서 리스너 이전) — 무해 ✅ |

→ 직행키/Group A 제거로 **새로 깨지는 튜토리얼 스텝 없음**. 리뷰 06이 예고한 "Group A 죽은코드 청소 시 동반 정리"와 일치.
