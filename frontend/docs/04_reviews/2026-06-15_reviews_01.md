## 이슈 목록

### ⚪ Nit — Foundation 고스트 색 판정 이중 호출
- 위치: `OJJ_BuildController.cpp:1064`
- 내용: 고스트 valid 판정에서 `CanPlaceFoundation`을 한 번 더 호출(호버 타일 경로의 `Fit.bValid`와 별개로 재평가).
- 영향: 미미 — 호버는 **셀 변경 시에만** 갱신되므로 프레임 비용 없음. 8×8 풋프린트 셀 순회 1회 추가뿐.
- 제안: 유지 가능. 굳이 줄이면 `OJJ_UpdateFoundationHoverPreview`가 내부 판정 결과를 out-param으로 돌려 공유. 현 상태로도 무방.

### ⚪ Nit — 머신 고스트 ZOffset의 "메시=루트 정렬" 가정
- 위치: `OJJ_Grid.cpp:OJJ_ShowGhostForMachine`(ZOffset 산출, `Mesh->GetBoundingBox().TransformBy(yaw+scale)`)
- 내용: 실제 배치 `GetMachinePlacementLocation`(OJJ_Grid.cpp:743-751)은 **라이브 컴포넌트 상대 트랜스폼**으로 ZOffset 산출. 고스트는 CDO라 라이브 트랜스폼이 없어 yaw+scale만 적용한 메시 AABB를 사용 → 메시 컴포넌트가 액터 루트에 상대 오프셋(위치/회전)을 가진 머신이면 고스트 Z가 실제 배치와 미세하게 어긋날 수 있음.
- 영향: 대부분 머신은 메시가 루트 정렬이라 영향 0. 오프셋 메시만 소폭 Z 차.
- 제안: PIE에서 다양한 머신으로 고스트 바닥 안착 육안 확인. 어긋나면 후속에서 CDO 메시 컴포넌트의 `GetRelativeTransform()`을 반영(현재도 CDO에서 읽기 가능).

### ⚪ Nit — 평판 슬래브 100uu/중심피벗 가정
- 위치: `OJJ_Grid.cpp:OJJ_ShowGhostForFoundation` (`Scale.Z = Thickness/100`, `SlabCenterZ = ... + Thickness*0.5`)
- 내용: 엔진 Cube가 100uu·중심 피벗이고 `UpdateSlabVisual`이 슬래브 중심을 상대 Z `Thickness/2`에 둔다는 전제로 재현. executor가 `UpdateSlabVisual`/`PlaceFoundationAtCursor` 대조 확인했고 `OJJ_ComputeSnapLift`를 CDO로 동일 호출(호버=배치 정합).
- 영향: 전제 성립 시 정확. Cube 메시/피벗을 바꾸면 어긋남.
- 제안: PIE에서 평판 고스트가 실제 슬래브와 동일 높이/크기인지 1회 확인.

### ⚪ Nit(설계상 의도) — GhostBaseMaterial 미지정 시 비활성
- 위치: `OJJ_Grid.cpp:OJJ_EnsureGhostMIDs`
- 내용: 머티리얼 미지정이면 1회 경고 후 고스트 no-op(크래시 없음).
- 영향: 에디터에서 반투명 머티리얼(파라미터 `TintColor`/`Opacity`)을 만들어 Grid의 `GhostBaseMaterial`(Category `Grid|Ghost`)에 지정해야 고스트가 보임. **사용자 후속 에디터 작업 필수.**
