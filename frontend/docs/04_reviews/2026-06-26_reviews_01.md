# 코드 리뷰 — 빌드모드 TPS(3인칭 설치) 1~3단계

- **일자**: 2026-06-26
- **리뷰어**: Codex (gpt-5.4) 위임 리뷰 + Claude 평가
- **대상**: 빌드모드 TPS 추가 1~3단계 (워킹트리 uncommitted)
- **빌드**: UE 5.7 `Wanted_FactoryEditor` Development 통과

## 변경 요약

탑다운 빌드모드에 새티스팩토리식 TPS(3인칭) 설치모드를 **병행 추가**. 전부 OJJ 도메인(BuildController/Player/Grid), 팀(AMachineBase/AConveyor/APowerLine) 코드 무변경.

대상 파일:
- `Source/Wanted_Factory/Public/OJJ_BuildController.h`
- `Source/Wanted_Factory/Private/OJJ_BuildController.cpp`
- `Source/Wanted_Factory/Public/OJJ_Player.h`
- `Source/Wanted_Factory/Private/OJJ_Player.cpp`

단계별:
- **1단계**: `EBuildViewMode{None,TopDown,TPS}` enum 신설 → 기존 `bool bIsBuildMode` 대체. `IsInBuildMode()=(Mode!=None)`로 14개 호출처 호환. B=TopDown / V=TPS 입력. `HandleBuildModeKey`(토글규칙: 현재==대상?None:대상) + `BuildController::SetBuildViewMode`(절대세터).
- **2단계**: `ApplyBuildModeView(bool)`→`(EBuildViewMode)` 3-way 분기. `ApplyBuildInputContext`(후보 IMC 전부 제거 후 목표만 추가 + 미할당 락아웃 가드). `HandleBuildModeKey`가 모드 실제변경 시에만 호출(TopDown↔TPS 전환 포함).
- **3단계**: `ResolveBuildTraceHit`(TPS=화면중앙 deproject + LineTrace + 10m 클램프), 커서레이 3곳 교체(`UpdateMouseHover`/`GetCursorCell`/`GetPowerLineEndpointUnderCursor`). `Zoom()` 가드 `IsInBuildMode()`→`GetBuildViewMode()==TopDown` 한정.

## 이슈 목록

### 🔴 Blocker

### 🟠 Major

#### M1. 빌드 종료 시 IMC_Player 미할당이면 빌드 IMC 잔류 → 입력 먹통 (회귀)
- **위치**: `Source/Wanted_Factory/Private/OJJ_Player.cpp:1307` (`ApplyBuildInputContext`, 수정 전)
- **내용**: 종료(None) 시 `Desired = IMC_Player`인데 null이면 `if(!Desired) return`으로 빌드 IMC를 제거하지 않고 빠져나감.
- **영향**: 빌드모드를 나왔는데 `IMC_Build`/`IMC_BuildTPS`가 활성 잔류 → 이동/시점/상호작용 입력 먹통. 기존 Exit는 IMC_Player null이어도 IMC_Build를 항상 제거했으므로 방어동작 회귀. (현실 확률은 낮음 — IMC_Player null이면 스폰부터 무입력이라 빌드 도달 불가하나, 방어코드 회귀라 수정.)
- **제안**: None(Exit) 케이스 분리 — 빌드 IMC는 무조건 제거, IMC_Player는 있으면 복원, 락아웃 가드는 진입/전환 한정.
- **상태**: ✅ **수정 완료** (2026-06-26). None 케이스 분리 적용.

#### M2. TPS 수면 보정이 마우스 레이 사용 → 크로스헤어-셀 어긋남
- **위치**: `Source/Wanted_Factory/Private/OJJ_BuildController.cpp` `ResolveCursorCellOverWater` 내부 (`DeprojectMousePositionToWorld` 직접 호출)
- **내용**: TPS에서 `Hit.Location`은 화면중앙 레이로 얻지만 수면/해안 보정은 OS 마우스 커서 레이로 재계산.
- **영향**: TPS 물 위(펌프 등) 배치 시 크로스헤어가 겨냥한 위치와 선택 셀이 어긋남. **TopDown 무영향(회귀 아님)**.
- **제안**: `ResolveCursorCellOverWater`에 모드 인식 추가(TopDown=마우스 / TPS=뷰포트 중앙 deproject).
- **상태**: ⏳ 후속 — TPS 물 배치 활성화 전 처리. (3단계 PIE 확인포인트 #3로 기록됨)

#### M3. TPS 파이프 출력포트 스냅이 마우스 커서 기준
- **위치**: `Source/Wanted_Factory/Private/OJJ_BuildController.cpp:1230` (파이프 드래그 시작, `OJJ_FindLiquidOutputPortUnderCursorScreen(PC, 64px)`)
- **내용**: `GetCursorCell`은 모드 인식됐으나 파이프 출력포트 스냅은 여전히 "커서 아래" 탐색.
- **영향**: TPS에서 마우스 근처 포트가 크로스헤어 선택셀을 덮어써 파이프 시작셀 오선택. **TopDown 무영향(회귀 아님)**.
- **제안**: 모드 인식 포트 스냅(화면 좌표 인자) 또는 TPS=뷰포트 중앙 분기.
- **상태**: ✅ **수정 완료** (2026-06-26, 파이프 TPS 2클릭과 함께). `OJJ_FindLiquidOutputPortUnderCursorScreen`에 `bUseScreenCenter` 인자 추가(TPS=뷰포트 중앙 기준), 호출부에서 `IsTwoClickConnectMode()` 전달.

## 우선순위 권고

## 긍정적인 부분

- `bIsBuildMode`→`EBuildViewMode` enum 마이그레이션이 `IsInBuildMode()` 동치 유지로 14개 호출처 무변경 호환 — 깔끔한 회귀 차단.
- `ResolveBuildTraceHit`의 null/뷰포트/deproject 실패 가드가 견고.
- 커서레이 소스를 3곳 모두 단일 함수로 통일 → 고스트=설치 좌표 일관성 확보.
- TopDown 기존 경로(커서 트레이스)를 그대로 보존 — TPS 추가가 기존 동작에 회귀 주지 않음.
