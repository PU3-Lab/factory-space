# 2026-06-21 코드 리뷰 01 — Foundation 다리를 라이브 트레이스로(절벽 4코너 깊이)

- **대상**: 절벽(급경사) Foundation 다리(leg)가 벽 표면에 얕게 걸치던 문제. 셀 대표 baked GroundZ → 다리 실제 월드 XY 라이브 하향 트레이스로 코너별 깊이 산출.
- **리뷰 범위**: `OJJ_Foundation.cpp`(UpdateLegVisual), `OJJ_Grid.h/.cpp`(신규 `OJJ_TraceTerrainZAtWorldXY` 배치)
- **리뷰 방식**: codex 진단(이론 A/B 충돌 확정) + codex 최종 review(파리티/코너/폴백/성능/dangling) + PIE
- **PIE**: 통과 — 절벽 벽 4코너 깊이 안착, 평지/일반 다리 회귀 없음, WaterArea 위 다리도 박스 안 걸림
- **빌드**: 통과

## 원인 (codex 확정)
`OJJ_Foundation`에 LineTrace 0건 = `UpdateLegVisual`이 코너별 `OJJ_GetRawTerrainSurfaceZ(CornerCell)`(baked 5점 최고점 = 셀 대표값)로 깊이 산출. 급경사 벽에선 다리 실제 XY의 벽면 깊이를 못 잡아 얕게 걸침. GroundZ 베이크 켠 뒤 드러남(전엔 폴백 1세그).

## 변경
- 신규 `OJJ_TraceTerrainZAtWorldXY(WorldXYs[], OutZ[], OutHit[])`: 베이크와 동일 채널/시작높이/깊이 + ignore(AMachineBase/AConveyor/AResourceBase(WaterArea)/AOJJ_Foundation). **ignore 목록 1회 구축 후 N점 트레이스**(코너 4점 재사용).
- `UpdateLegVisual`: 4코너 실제 월드 XY(`GetActorTransform().TransformPosition(PosX,PosY,0)`) 선산출 → 1회 일괄 트레이스 → 코너별 Height. 옛 CornerCell/CellHalf baked 조회 제거.

1. **트레이스 파리티**: OK — 채널/시작높이/깊이/ignore(WaterArea 포함) 베이크와 일치. ✅
2. **코너 XY**: OK — 다리 실제 월드 XY 트레이스, baked CornerCell 잔존 없음, CellHalf 제거. ✅
