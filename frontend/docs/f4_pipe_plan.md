### 핵심 호재 — 벨트보다 침습이 작다
세그먼트가 셀쌍 사이 **실린더 + `FQuat::FindBetweenNormals(Up, 방향)` + 길이 스케일**(Pipe.cpp:254-256)
— **임의 3D 방향 네이티브**. 벨트는 pitch/길이 수식 2지점을 새로 깔아야 했지만(F3.7-0 #2·#3),
파이프는 시작/끝점에 **Z항만 넣으면 기울기·길이가 자동**. 침습 = "셀별 Z 채널(멤버+세터+Z항)" 1커밋.

## 2. 교차 공존 — 점유 2D 한계 해법

현황: `OccupiedCells = TMap<FIntPoint, TWeakObjectPtr<AActor>>` 셀당 1액터. 컨베이어 경로 검증이
점유 셀을 차단하고, 등록 API(:812-814)는 "다른 actor 점유 셀 충돌 거부"가 데이터 무결성 가드.

- **(a) 통과 허용 마크**: OccupiedCells 유지 + 교차 셀에 파이프 통과 표식 별도 기록.
  - 단점: "셀당 1액터" 불변식을 우회하는 예외 데이터가 생김(철거 동기화·질의 소비처 전수 수정),
    파이프↔파이프 교차 표현 불가, 마크의 소유 액터가 모호(컨베이어 철거 시 마크 고아).
- **(b) 파이프 전용 레이어 (추천)**: `PipeCells = TMap<FIntPoint, FOJJPipeCellInfo>` 신설 —
  **Foundation 커버리지(FoundationCells)가 이미 같은 패턴의 독립 레이어 선례**. 머신/컨베이어
  점유와 직교하고, 레이어 간 규칙(교차 허용/차단)을 명시 코드로 표현. weak ptr 자동 무효화·
  철거 경로도 Foundation 미러로 기성 패턴.
  - FOJJPipeCellInfo: 파이프 액터 weak + **셀별 Z(지상/공중 구분 — §3 역방향 규칙의 입력)**.
- (c) 일반 다층 점유: 베타 유지 전제로 기각(요구에 없는 일반화).

## 3. 교차 Z — 오버패스 산출/주입

- **주입 패턴**: 그리드가 경로 셀별 Z 배열 산출 → 파이프 세터 주입 — **F3.7-0(벨트 Z 채널) 미러**.
  파이프 침습 = 멤버 `TArray<float>` + `OJJ_SetPathCellLocalZs` 세터 + Z항 2함수(RebuildVisuals,
  GetCellLocalCenter — 액체 비주얼도 같은 함수라 자동 추종). 빈 배열 = 평면 항등(기존 BP 경로 무회귀).
- **산출(그리드 측)**: 기본 셀 Z = 경로 SurfaceZ 추종(Foundation 위 파이프 — §결정 ㉦), 교차 셀 =
  컨베이어 상면 + 클리어런스(㉢). 교차 셀 양옆 ±1칸에서 상승/하강(1칸 45° 실린더 — F3.10 1칸
  쐐기와 동일 정신, 세그먼트가 3D 네이티브라 형상 작업 0).
- **역방향(컨베이어가 나중에 파이프 셀 통과) — 비대칭 (추천, 명시)**:
  - 파이프 = 항상 양보(나중에 깔리는 쪽이 타넘기). 컨베이어가 나중이면 **거부** + 사유
    ("파이프 점유 — 우회 또는 파이프 철거"). 벨트 타넘기는 세그먼트 pitch·아이템·경사 코너
    금지(㊅)·포트 정합까지 연쇄돼 범위 폭발 — F4 밖.
  - 완화 후보(결정 ㉡): **공중 파이프(오버패스로 떠 있는 셀) 아래는 컨베이어 통과 허용** —
    PipeCells의 셀별 Z로 판별 가능(지상 파이프 셀만 차단). 허용 시 "파이프 먼저, 벨트 나중"
    순서도 성립해 UX 대칭에 근접.

## 4. 펌프/물탱크 포트

- MachineTable SSOT 등재 확인: Pump 3×3 **In 1/Out 1**, LiquidTank 5×5 **In 1/Out 1** —
  컨베이어 끝점 패턴(`OJJ_IsMachineBackOutputPair` 출력 포트쌍 + `OJJ_FindInputMachineAtPathEnd`
  입력 + `GetOutputPortCount` 게이트)을 **그대로 재사용 가능. 파이프 전용 포트 신설 불필요.**
- Pipe 자체도 테이블에 1×1·포트 0/0으로 등재(Pipe_Lv1~3) — 컨베이어처럼 "머신 아닌 경로
  액터"로 취급하고 테이블 행은 비용(iron_ingot 10)/BOM 소비용으로 해석.
- 액체 한정은 현재 런타임 필터(파이프 내부 `IsLiquidItem`)만 — 배치 시점 사전 차단은 ㉤.

## 결정점 목록 (승인 대기)

- **㉠ 점유 모델**: (a) 통과 마크 vs **(b) 파이프 전용 레이어 — 추천**(Foundation 선례, 무결성 가드 보존).
- **㉡ 역방향 규칙**: 컨베이어→지상 파이프 셀 = 거부(추천). **공중 파이프 아래 통과 허용** 여부 —
  허용 추천(PipeCells 셀별 Z로 판별 기성, 배치 순서 자유도 확보). 비대칭(벨트는 타넘기 없음)은 명시 수용.
- **㉢ 클리어런스**: 교차 셀 파이프 하단 = 컨베이어 상면 + X uu. 후보: 아이템 비주얼 최대 높이 실측 후
  결정(기본 50 제안 — 단 간격 100의 절반, 파이프 상승 1칸 45° 이내 유지).
- **㉣ 오버패스 형상**: 교차 셀 ±1칸 45° 상승/하강(추천 — 1칸 쐐기 동일 정신) vs 완경사 ±2칸.
  연속 교차(컨베이어 2열 나란히)는 내림 없이 공중 유지로 병합 — 산출 로직에 포함할지.
- **㉤ 액체 게이트 시점**: 배치 시 "펌프류(액체 출력) 출발 + 탱크류(액체 입력) 도착" 사전 차단 vs
  런타임 필터만(현행). 사전 차단 추천 — 잘못 깐 파이프의 침묵 유휴를 빨강+사유로 조기 노출.
- **㉥ 파이프↔파이프 교차**: F4 거부(레이어 내 단일 점유 — 자연 거부) 추천, 지원은 후속.
- **㉦ 파이프 높이 일반화**: 기본 Z부터 경로 SurfaceZ 추종(Foundation 위 파이프 — 벨트 F1-c 패리티)
  포함 추천 — Z 채널이 어차피 생기므로 한계비용 0. 경사(램프 위) 파이프는 F4 밖.
- **㉧ Chan 협업**: Z 채널 1커밋(빈 배열 수치 항등 검증 — F3.7-0 ① 미러) 사전 허락. 허락 전까지
  그리드측(배치/레이어/검증)은 선행 가능 — 평면 파이프로 기능 성립, 오버패스만 Z 채널 대기.
