# 물 시스템 설계 — 웅덩이(고인 물) 방식 (#197 / #160 / #182 연계)

> 작성 2026-06-15. **설계 문서**(구현 X).
> **확정 방향**: 랜드스케이프로 **봉우리**를 올려 사이에 **웅덩이** → 고인 물. 흐르는 강(WaterArea 라인) **불채택**.
> 수면은 **정적 평면**(지형 추종 불필요) + **흐르는 머티리얼**(UV 패닝으로 물결 느낌).
>
> **재료(준비됨)**: 물 머티리얼 **`Content/OJJ/Materials/M_Water.uasset` 신규 제작 완료**(흐르는 비주얼). 3단계는 "**적용만**".

## 조사 — 현재 물 분류 vs 웅덩이 요구

### 물은 두 시스템 (이전 진단 유지)
- **A. WaterArea 액터**(`Resource/WaterArea`): **평탄 플레인** + 셀 점유 + `form="liquid"` 펌프 수원. → 웅덩이엔 **이 평탄 플레인이 오히려 딱 맞음**(고인 물 = 수평면, 지형 추종 불필요).
- **B. Water 셀 분류(베이크, `OJJ_Grid.cpp:929~937`)**: `bWater = bAnyHit && (LowestSignedDelta < WaterSurfaceZ)`. 셀 최저 지형이 수면선보다 깊으면 Water. → **어느 셀이 물에 잠겼나**의 진실원.
- ⚠️ 현재 둘은 디커플링(베이크가 AResourceBase ignore). 웅덩이 방식에선 **B(깊이 분류)를 진실원**으로 삼고, A는 **수면 비주얼/차단**으로 역할 분담하면 정합된다.

### 웅덩이 깊이 임계(WaterSurfaceZ)를 어떻게 잡나
- `WaterSurfaceZ`는 **그리드 평면 Z(액터 Z) 상대 수면 높이**. 셀 최저점이 이보다 **아래**면 물.
- 핵심: **수면선을 어디 둘지** = WaterSurfaceZ 값. 권장 운용 —
  - 디자이너가 **그리드 평면을 의도한 수면 높이에 맞춰** 두고, 웅덩이는 그 아래로 판다.
  - `WaterSurfaceZ` ≈ **0 ~ 약간 음수**(예: −10~−30) — 얕은 가장자리 노이즈만 제외, 웅덩이 바닥은 확실히 물로.
  - 현재 기본 **−20**은 "평면보다 20uu 깊어야 물" — 봉우리를 평면 위로 올리는 방식이면 웅덩이 바닥이 평면 근처/위일 수 있어 **분류 0** 가능. → **봉우리는 평면 위로, 웅덩이는 평면 아래로** 조형하거나 WaterSurfaceZ를 맵 조형 실측에 맞춰 재설정.
- ⚠️ **현재 `water N` 값은 PIE 확인 필요**(`[Grid] Bake ... water N`). 0이면 위 임계/조형 불일치 확정. (코드로는 PIE 미실행 — 사용자 확인 항목)
- 분류는 **5점 샘플 최저 델타** 기준(`LowestSignedDelta`) — 셀 일부만 잠겨도 물로(가장자리 over-inclusive, 자연스러움).

### 웅덩이 방식이 없애는 문제
- **"물 지형 추종"(이전 2단계, 가장 무거웠음) → 불필요.** 고인 물은 **수평 평면** 하나면 됨(WaterArea 플레인 그대로). 비주얼 작업 대폭 축소.

## 설계 (4영역)

### 1. 맵 조형 (에디터) — #160 맵 연계
- 랜드스케이프로 **봉우리(평면 위) + 웅덩이(평면 아래)** 조형. 웅덩이는 `WaterSurfaceZ`보다 확실히 깊게.
- 봉우리 경사가 **#188 눈/땅 마스크**에 자연스러운 입력(아래 보너스).
- ⚠️ 의존: 조형 후 그리드 **Rebake** 필요(분류 갱신).

### 2. 로직 — 웅덩이=물 영역, 펌프=물 위
- **물 영역 진실원 = B 분류**(`WaterSurfaceZ` 임계). 조형+Rebake로 `WaterCells > 0`.
- **펌프 = 물 위(#182)**: 현재 펌프는 물 **인접**(`Pump.h:25` 4방향 form=liquid). 웅덩이 방식이면 **펌프를 물 셀 위에 배치** 허용으로 변경 —
  - water 셀을 **펌프 한정 placeable**로(다른 건물엔 여전히 거부), 또는 펌프 `CanPlaceAdditional`을 "발밑 또는 인접 water"로 확장.
  - ⚠️ WaterArea 점유와 충돌 주의 — water 셀을 점유 레이어에서 빼고 **별도 water 레이어**(FoundationCells 패턴)로 두면 펌프만 예외 허용이 깔끔.
- 파이프=물·땅·Foundation 통과 / 컨베이어=땅·Foundation(현행).

### 3. 비주얼 — 정적 수면 + 흐르는 머티리얼 (**머티리얼 이미 제작 → 적용만**)
- **머티리얼 준비됨**: `M_Water.uasset` 신규 제작(흐르는 비주얼). 이 단계는 **만드는 게 아니라 물 영역에 적용**.
- **수면 = 수평 평면**(WaterArea WaterPlaneMesh 재사용 또는 웅덩이 영역 단일 플레인) at `평면Z + WaterSurfaceZ`에 `M_Water` 입힘.
- UV 패닝(FlowVelocity)으로 고인 물에도 물결/반짝임. 깊이 기반 투명도/색(선택).
- z-fighting: 수면은 지형 위 평면이라 #215 그리드 z-fight와 무관(수면 Z 고정).

### 4. 보너스 — 봉우리 경사 → #188 눈/땅 자동
- **완만 지형 문제 해결**: #188이 Threshold 0.99/Falloff 0.01 극단값을 쓴 이유가 "지형이 완만"이라서였음. **봉우리를 올리면 경사가 가팔라져** Normal.Z 변화 폭이 커짐 → **자연스러운 Threshold(0.85~0.92)로 봉우리=눈/평지·웅덩이=땅** 자동.
- → #160 조형이 #188을 **소급 개선**(극단값 완화 가능).

## 단계 분해 + 의존성

| 단계 | 작업 | 작업량 | 의존성 |
|---|---|---|---|
| **0. PIE water N 확인** | 현재 분류 셀 수 진단 | 5분 | 없음 (시작) |
| **1. 맵 조형 (#160)** | 봉우리/웅덩이 랜드스케이프 + 그리드 정렬(수면=평면 높이) | 중(에디터) | 0 |
| **2. 물 분류 살리기 (#197)** | WaterSurfaceZ 조형 실측 맞춤 + Rebake → WaterCells>0 | 소(튜닝/리베이크) | 1 (조형 후 실측) |
| **3. 수면 비주얼** | 웅덩이 평면에 `M_Water`(이미 제작) **적용만** | 소(적용) | 2 (어디가 물인지) |
| **4. 펌프=물 위 (#182)** | water 셀 별도 레이어 + 펌프 배치 예외 | 중(코드) | 2 (water 셀 진실원) |
| **5. #188 재튜닝(보너스)** | 봉우리 경사로 Threshold 자연값 복귀 | 소 | 1 (봉우리 조형) |

### 의존성 사슬
```
#160 맵 조형(봉우리/웅덩이) ──┬─→ #197 물 분류(WaterSurfaceZ 실측+리베이크) ──┬─→ #182 펌프=물 위 배치
                              │                                              └─→ 수면 비주얼(평면+UV패닝)
                              └─→ #188 눈/땅 재튜닝(경사 자연값) [보너스, 독립]
```
- **#160(조형)이 최상류** — 봉우리/웅덩이가 있어야 #197 분류도, #188 경사도 의미가 생김.
- **#197(분류)이 허브** — #182 배치와 비주얼의 공통 입력(water 셀 진실원).
- **#182(펌프)는 최하류** — water 셀 정의 확정 후.

### 가장 먼저
1. **PIE `water N` 확인** (현재 0인지).
2. **#160 조형 1차**(봉우리 하나 + 웅덩이 하나) + **그리드 평면을 수면 높이에 정렬** → Rebake → `WaterCells>0` 확인(#197 2단계).
3. 그 셀이 #215 파랑 윤곽선으로 보이면 → 진실원 살아남 → #182 펌프 배치 + 비주얼로 확장.

> ⚠️ 1차 조형 전 결정: **그리드 평면 Z = 수면 높이**로 합의(봉우리는 위로, 웅덩이는 아래로). 이래야 `WaterSurfaceZ≈0~−30` 단순 임계로 웅덩이가 깔끔히 분류됨.
