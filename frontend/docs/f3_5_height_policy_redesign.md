# F3.5 — Foundation 높이 정책 재설계: 지형 스냅 → 이웃 상속 (새티스팩토리 정합)

작성일: 2026-06-11 · 선행: F3-2(`f59be13`) · 상태: **구현 완료(빌드+Codex PASS, `a70c466`·`b9b4691`) — PIE 검증 후속**

## 배경 — F3 PIE 검증의 구조적 발견

F2-4의 "지형 자동 스냅"(N = ceil((풋프린트 max GroundZ − Thickness)/100))은 **새티스팩토리와 정반대
철학**: 새티스팩토리는 지형을 무시하고 **이웃 높이 상속으로 평면을 확장**하며(지형 클리핑 허용),
램프는 이웃 판 엣지에 스냅한다. 현 구조의 실증된 문제(경사지):

- **평면 확장 불가** — 인접 장이 셀 지형 따라 제각각 단이 됨(N, N+1, N+2…)
- **컨베이어 단절** — 단이 갈라진 인접 판 걸침은 이높이 거부(의도된 규칙이 의도 못한 곳에서 발동)
- **램프 부유** — 램프가 이웃 판이 아니라 지형 기준으로 떠서 연결 대상과 안 맞음

원인은 산식이 아니라 **높이 결정의 진실원**: 지형(현행)이 아니라 **이웃 판(새 정책)**이어야 한다.
지형은 첫 장(씨앗)의 기준일 뿐.

---

## 1. 새 높이 결정 우선순위

```
① 인접 Foundation 있음  → 높이 상속 (이웃 SurfaceZ 그대로 — 평면 확장, 기본 경로)
② 고립(인접 없음) 첫 장 → 현행 N 산식 (풋프린트 max GroundZ 스냅 — "씨앗")
③ 램프               → 인접 판 엣지 스냅: 낮은 끝 = 이웃 SurfaceZ, 높은 끝 = +1단(+100)
                       (낮은 끝에 이웃 없으면 ② 씨앗 폴백 — 고립 램프 = 지형 오르기 용도)
```

- ①의 "상속"은 단 격자 보존: 이웃 SurfaceZ = 평면+Thickness+N×100 이므로 상속값도 자동으로 격자 위
  — OJJ_GetUniformSurfaceZ 동일성·걸침 허용·㉲ 불변식 전부 그대로 성립.
- ③ 높은 끝 +100은 단 간격 고정(OJJ_FoundationSnapStep) 덕에 높은 쪽 이웃과도 자동 일치.
- 평면 확장이 기본이 되므로: 같은 단 평면이 경사지를 가로질러 자라고, 그 위 컨베이어는 균일
  SurfaceZ로 자동 연결 — F3 발견 3문제의 직접 해소.

## 2. 지형 클리핑 허용 — 영향 점검

상속 평면이 오르막을 파고들면 슬래브가 지형에 박힌다(새티스팩토리 동일). 코드 영향:

| 영역 | 영향 | 판정 |
|---|---|---|
| 베이크 | 없음 — ↓트레이스가 `TActorIterator<AOJJ_Foundation>` ignore(파생 포함), 분류는 지형만 | ✅ 무변경 |
| 걷기 충돌 | 슬래브 Pawn Block이 지형 내부에 있어도 캐릭터는 지형 위 — 간섭 없음. 노출면부터 걸을 수 있음 | ✅ 수용 |
| 커서 트레이스 | 묻힌 셀은 Landscape 선히트 — F2-1' 게이트가 이미 허용, XY 셀 매핑 동일 | ✅ 무변경 |
| 호버/비주얼 타일 | `OJJ_GetCellVisualBaseZ`가 Foundation 상면 우선 → 묻힌 셀 타일이 지형 아래로 숨음 | ⚠️ 결정 ㉻-b |
| 머신/컨베이어 배치 | 묻힌 셀 위 배치 시 SurfaceZ가 지형 아래 → 액터 묻힘(새티스팩토리도 동일 클리핑) | ⚠️ 결정 ㉻ |
| 올려태우기 | 발 ≥ 상면이면 no-op — 묻힌 슬래브는 자연히 발동 안 함 | ✅ 무변경 |
| 철거/점유/커버리지 | 높이 무관 레이어 | ✅ 무변경 |

**변경 국한성 검증**: 변경은 ① `OJJ_ComputeSnapLift` 훅 내부(평판 베이스 구현 — 이웃 우선 + 씨앗 폴백,
램프 오버라이드 — 이웃 엣지 우선 + 폴백)와 ② 신규 그리드 둘레 조회 헬퍼 — **2지점**.
`PlaceFoundationAtCursor`는 이미 훅 경유(F3-2 Codex ② 수정의 부수 효과로 호출부 무변경),
등록·검증·비주얼·소비처는 산식 결과만 받으므로 무접촉. ✅ 사용자 가설(높이 산출 + 램프 스냅 기준에
국한) 성립 — F3-2에서 훅을 미리 분리해 둔 덕.

## 4. 결정점 목록 (검토 대상)

- **㉶ 인접 판정 범위**: **면접촉(풋프린트 둘레 4방 셀)만 — 추천**. 대각은 모서리 한 점이라 평면 확장
  의미가 약하고 의도치 않은 상속 유발. 새티스팩토리도 엣지 스냅.
- **㉷ ✅(보강)** 다중 인접 단 충돌: 접촉 셀 수 최다 단, 동률이면 낮은 단.
  **보강 — 배치 로그에 높이 출처 구분**: `상속 N=x (이웃 접촉 y셀)` vs `씨앗 N=x (지형)` —
  정책 동작 실측/디버깅 데이터(F2 결정 ⑤ N 로그와 같은 취지).
- **㉸ 수직 너지 키**(의도적 다른 단 시작 — 테라스): **F3.5 범위 밖, 백로그 — 추천**. 고립 씨앗 +
  램프로 단 전환이 가능하므로 당장 불필요. 필요 시 PgUp/Dn ±1단.
- **㉹ 램프 낮은 끝 이웃 없음**: **씨앗 산식 폴백 — 추천**(고립 램프 = 지형 오르기 용도 유지).
  대안: 거부(램프는 연결 전용) — 용도 축소라 비추천.
- **㉺ 호버 프리뷰 높이 표현**: 현행 셀 타일 유지(높이 미표현) — **추천**(F2 결정 ⑦ 일관).
  상속 높이의 사전 피드백은 UX 백로그.
- **㉻ 클리핑 셀 위 머신 배치**: **(a) 수용 — 추천**(새티스팩토리 동일, 정책 일관) vs (b) 묻힌 셀
  배치 거부(SurfaceZ < 지형 셀에 게이트 — 규칙 추가). **㉻-b 묻힌 셀 호버 타일**: 지형 아래로
  숨는 것 수용 — 추천(타일 Z = max(상면, 지형)는 시각=데이터 단일원 훼손).
- **㉼ §5-2 직배치와의 관계**: 직배치(머신/컨베이어 지형 위)는 계속 지형 기준 — 본 재설계는
  Foundation 높이 정책만. F4(직배치 은퇴) 논거가 더 강해짐(상속 평면이 사실상의 건설면).

## 리뷰 관점 추가 (승인 보강)

- 인접 스캔의 **stale Foundation 상속 차단**: 둘레 조회가 `GetFoundationSurfaceZ`(weak `IsValid`
  검증) 경유인지 — 파괴된 Foundation의 잔존 셀에서 높이를 상속받으면 유령 단이 생긴다.

## 검증 계획 (구현 승인 후)

경사지에서: 씨앗 1장 → 4방 확장 시 전부 같은 단(평면) → 그 위 컨베이어 연결 → 램프 낮은 끝이
이웃과 턱 0 / 높은 끝 +100 → 클리핑 슬래브 노출면 걷기 → 고립 씨앗·고립 램프 폴백 동작.
