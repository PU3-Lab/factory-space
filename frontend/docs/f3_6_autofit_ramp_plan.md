> 개념: 램프 모드 호버 시 회전 축 양방향으로 이웃 Foundation을 스캔 → 틈 D칸 + 높이차 ΔZ로
> 길이/경사를 자동 산출. 행당 계단 ≤ 45uu 검증(미달 시 빨강 + 최소 칸수 사유), 양 끝은 이웃
> 높이와 정확 일치(턱 0). 양쪽 이웃이 없으면 기존 고정 램프로 폴백.

## 1. 산식 — 기존 턱 0 산식의 일반화 (신규 산식 아님)

현행(F3-2): `SurfaceZ(r) = Z_low + (r/(R−1))×100`, R = FoundationSize.X 고정, 상승 1단 고정.
자동 맞춤은 두 변수만 일반화:

```
R = D (스캔된 틈 칸수),  상승 = ΔZ = k×100 (k = 이웃 단 차이 — 항상 정수, 아래 보장)
SurfaceZ(r) = Z_low + (r/(D−1)) × k×100,   행간 계단 = k×100/(D−1) ≤ 45
```

- **k 정수 보장**: 양 이웃 Z는 `OJJ_GetDominantFoundationSurfaceZInRect`가 단 격자(평면+Thickness
  기준 100 정수배) 위 값만 집계(Codex F3.5 C 게이트) — 램프 중간 행 등 비격자는 후보 제외라
  ΔZ는 구조적으로 100의 정수배. (전 Foundation 클래스 Thickness 45 동일 전제 — F3.5와 같은 전제.)
- **양 끝 정합**: r=0 → Z_low 정확(낮은 이웃과 동일), r=D−1 → (D−1)/(D−1)=1이라 Z_low+k×100
  정확(float 오차 0) — 기존 보강 산식의 성질이 k단으로 그대로 확장. 걸침 배치/도보 턱 0 자동.
- **최소 칸수**: D−1 ≥ k×100/45 → 미달 시 빨강 + "틈 D칸 < 최소 X칸(k단)" 사유.

| k (단차) | 최소 D | 그때 행당 계단 |
|---|---|---|
| 1 (100uu) | 4칸 | 33.3uu |
| 2 (200uu) | 6칸 | 40.0uu |
| 3 (300uu) | 8칸 | 42.9uu |
| 4 (400uu) | 10칸 | 44.4uu |

다단(k≥2) 연결이 공짜로 따라옴 — 고정 램프를 단마다 이어 붙이는 것 대비 UX 우위.

## 2. 구조 수용성 — ㉲ 셀→Z 배열 + 스냅 훅 (질문 ①)

### 그리드 측: **무변경** ✅
| 구성요소 | 판정 | 근거 |
|---|---|---|
| `OJJ_TryPlaceFoundationPerCell` 불변식 | ✅ 그대로 통과 | 검증 ③이 "(max−min) = 단 간격의 **정수배**"(OJJ_Grid.h:619) — 1단 전용으로 쓰여 있지 않아 k×100 수용. 배열 크기·유한값 검증도 D×W에 그대로 |

| 램프 `OJJ_ComputeSnapLift`(F3.5 ③ 엣지 스냅) | ✅ 무변경 | 자동 풋프린트가 틈에 정확히 끼면 "낮은 끝 바깥 인접 라인" = 낮은 이웃 그 자체 — 기존 훅이 그대로 Z_low 산출. 높은 끝 일치는 §1 산식이 보장 |
| 프리뷰 폭주 방어 | ✅ 기성 | MaxPreviewCells 4096 가드(OJJ_Grid.cpp:1753) — 동적 D×W도 커버 |

### 액터/컨트롤러 측: 일반화 2건 + **신규 훅 1건** (이게 실변경의 전부)
1. **`OJJ_BuildPerCellSurfaceZ` 일반화 — 회귀 0**: 현재 `R = FoundationSize.X`(RampFoundation.cpp:39)인데
   주석이 이미 "EffSize는 step 0/2에선 X, 1/3에선 Y가 R과 같다"고 동치를 명시 — R을 EffSize 축
   유도로 바꾸면 고정 램프 동작 비트 동일, 동적 크기는 자동 정합. 추가로 상승량 파라미터
   (`RiseSteps`, 기본 1) 필요 — 시그니처 확장(평판 base는 무시, 호출부 1곳).
2. **풋프린트 결정 훅 신규 — 유일한 구조 변경**: 현재 풋프린트는 컨트롤러가 CDO에서 정적 산출
   (`Size→EffSize→Origin`, BuildController :933-935 호버 / :962-964 배치). 자동 맞춤은 풋프린트가
   **커서+그리드 상태의 함수**라 이 지점이 훅이어야 함:
   ```
   virtual FOJJRampFitResult OJJ_ComputeHoverFootprint(Grid, CursorCell, RotationSteps)
     → { Origin, EffSize, RiseSteps(k), bAutoFit, bValid, FailReason }
   ```
   베이스 구현 = 현행 정적 수식(평판·고정 램프 회귀 0). 호버와 배치가 **같은 훅을 호출** —
   "미리보기 = 실제 배치" 단일원 정책(머신 경로 핵심 계약) 유지. k는 이 결과 구조체로
   `OJJ_BuildPerCellSurfaceZ`까지 스레딩(램프 액터에 스캔 상태 저장 금지 — 호버/배치 race 차단).
3. **검증 빨강 + 사유**: 경사 한계 위반은 `CanPlaceFoundation`(커버리지 검증) 밖의 클래스 논리 —
   프리뷰 색 = `CanPlaceFoundation && FitResult.bValid`, 클릭 거부 시 FailReason 로그
   ("틈 3칸 < 최소 4칸(1단)") — 기존 OutReason 로그 패턴과 동일(화면 표시는 ㉺ 일관 — 백로그).

**변경 국한성**: ①훅 신규(베이스+램프 오버라이드) ②퍼셀 훅 시그니처 ③컨트롤러 호버/배치 호출부
치환 — 3지점. 그리드·등록·검증·비주얼 소비처 무접촉. ✅ ㉲ 구조가 수용함.

### 비주얼
`UpdateSlabVisual`은 `FoundationSize` 기반(RampFoundation.cpp:134) — 동적 크기는 등록된 풋프린트/k를
액터에 확정 저장(배치 시 1회, `OJJ_NotifyPlacedOnGrid` 경유) 후 그리는 변경 필요 — 소.

## 3. 호버 프리뷰 동적 풋프린트 비용 (질문 ① 후반) — **수용 가능**

- **빈도**: 리빌드는 셀 변경 시만(동일-셀 스킵 :919, 회전은 sentinel 강제 갱신 :318) — 스캔도
  같은 빈도. Tick 아님.
- **스캔 비용**: 축 양방향 × MaxScan(제안 32칸) × 폭 W(8) 라인의 TMap 조회 ≈ 최대 512 lookup +
  지배 집계 — 어차피 같은 프레임에 도는 호버 ISM 리빌드(인스턴스 재생성)보다 쌈.
- **무효화 누락 리스크(소)**: 같은 셀 호버 중 이웃 판이 새로 생기거나 철거되면 프리뷰가 stale.
  배치는 sentinel 리셋(머신 :893 패턴)으로 커버, 철거는 모드 전환 경유라 실질 노출 작음.
  클릭 시 같은 훅이 **재스캔**하므로 정합성(배치 결과)은 항상 진실 — 어긋남은 미리보기 한정, 수용.

## 4. 한쪽/무이웃 폴백 (질문 ②) — **기존 고정 램프 그대로, 추가 작업 ~0**

스캔 결과로 분기:
- **양쪽 이웃** → 자동 맞춤(§1).
- **한쪽만** → 고정 램프(FoundationSize 길이, +1단). F3.5 ③ 엣지 스냅이 **이미 그 이웃에 Z를
  붙이는 동작** — 낮은 끝 쪽 이웃이면 현행 그대로, 높은 끝 쪽 이웃이면 Z_low = 이웃 −100으로
  붙이는 분기만 추가(소). 길이는 자동화하지 않음(한쪽 기준 길이는 정의 불능).
- **무이웃** → 씨앗 폴백(고립 램프 = 지형 오르기, ㉹ 결정 유지) — 무변경.

폴백 경로가 풋프린트 훅의 베이스 분기라 자동 맞춤 실패(미검출·한계 위반)와 "이웃 없음"이
한 함수에서 결정 — 호버/배치 불일치 원천 차단.

## 5. ㉯(8×8 vs 4×8) 불필요화 여부 (질문 ③) — **사실상 종결 가능**

- **판-판 연결(주 용도)**: 길이가 틈에서 자동 산출 — 크기 변형 자체가 무의미해짐. 4×8이 노리던
  "좁은 틈"은 1단 4칸부터 전부 커버(고정 변형보다 정밀).
- **고정 램프 폴백(고립/한쪽)**: `FoundationSize.X`가 여전히 길이 — 기본 8×8 유지로 충분.
  4×8 **변형 추가는 불필요**(폴백은 지형 오르기 용도라 완만한 8×8이 적합).
- **결론**: F3.6 채택 시 ㉯는 "**8×8 기본 확정 + 변형 도입 안 함**"으로 종결. 단 자동 맞춤
  자체가 PIE를 통과해야 하므로, ㉯ 태그는 F3.6 PIE까지 유지.

## 6. 결정점 목록 (검토 대상)

- **㉽ 풋프린트 결정 훅 도입**: 컨트롤러 정적 산출 → CDO 가상 훅(베이스 = 현행 수식) — **추천**.
  유일한 구조 변경이자 F3.6의 본체. 대안(컨트롤러에 램프 분기 하드코딩)은 F3-2 훅 패턴 위반.
- **㉾ MaxScan 거리**: **32칸 추천** — 1단 최대 D와 무관하게 긴 완경사 틈 커버 + 스캔 비용 상한.
  초과 틈은 미검출 → 폴백(고정 램프). EditAnywhere 노출.
- **㉿ ΔZ=0 틈(양 이웃 같은 단)**: **(a) 평지 브리지 허용 — 추천**(k=0이면 퍼셀 훅이 false 반환 →
  기존 단일값 등록 경로로 자연 퇴화 — D×W 평판, 코드 공짜) vs (b) 거부(램프는 경사 전용 —
  용도 축소라 비추천).
- **㊀ 폭 W**: **CDO FoundationSize.Y 고정(8) — 추천**. 이웃 폭 상속은 양쪽 폭이 다를 때 정의
  불능. 측면 정렬은 기존 커서 중심 수식(ComputeOriginFromCursorCellForSize의 수직 축 성분).
- **㊁ ✅(보강)** 회전 키 의미: 4방 유지하되 **자동 맞춤 시 부호는 이웃이 결정**(양방향 스캔이
  낮은 끝/높은 끝을 자동 판정 — 낮→높), 사용자는 축(X/Y)만. **한쪽 이웃/무이웃 폴백(고립 램프)일
  때만 R이 오르막 방향(부호)까지 의미를 가짐** — 입력 모델 변경 없음.
  **보강 — 방향 출처 이원화의 UX 방어**: 호버(풋프린트 산출) 로그에 방향 출처를 표시 —
  `방향 자동(이웃 낮→높)` vs `방향 수동(R)` (F3.5 ㉷ 높이 출처 로그와 같은 취지, F3.6-1에서 구현).
- **㊂ 한계 위반 사유 표시**: **클릭 시 로그 — 추천**(호버 색 단일 진실원 정책 + ㉺ 일관).
  호버 중 화면 텍스트는 UX 백로그.

## 검증 계획 (구현 승인 후)

경사지 두 단(N, N+1) 판 사이: 틈 4/5/8칸에서 자동 길이·경사 → 양 끝 턱 0 도보 + 걸침 배치 →
틈 3칸 빨강 + 최소 칸수 사유 → k=2 틈 6칸 다단 연결 → 한쪽 이웃(낮은 쪽/높은 쪽 각각) 고정
램프 폴백 → 무이웃 씨앗 폴백 → ΔZ=0 브리지(㉿ 채택 시) → 평판/고정 램프 회귀(훅 베이스 경로).
