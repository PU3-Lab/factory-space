# 코드 리뷰 — #7 버그 a: 세이브/로드 후 회전 램프 폭 좁아짐

- 날짜: 2026-06-27
- 리뷰 방식: 진단 로그 주입 → PIE 재현 → codex(GPT) 교차검증
- 영역: OJJ (OJJ_RampFoundation)

## 변경 요약

세이브→로드 후 **회전된 램프(Step 1/3)** 의 폭이 좁아지던 버그 수정(배치 직후엔 정상).

- 원인: 로드 시 `FactorySaveSubsystem`이 `SetFoundationSizeForSave`로 `FoundationSize`를 저장된 **비정사각 footprint**(회전 램프 = (8, GapLength))로 바꾼다. `ApplySaveState`는 climb을 parity(`(Step%2==0)?X:Y`)로 맞추지만, `UpdateSlabVisual`의 폭 `Cols`는 **항상 `FoundationSize.Y` 고정** → 회전 램프에서 `.Y`가 climb축 값(GapLength)을 집어 폭이 좁아짐. 배치 직후엔 `FoundationSize`=CDO `(8,8)` 정사각이라 숨음.
- 수정 (`OJJ_RampFoundation.cpp` `UpdateSlabVisual`):
  1. `Step` 계산을 `Cols` 앞으로 이동.
  2. `Cols = (Step%2==0) ? FoundationSize.Y : FoundationSize.X` — climb과 동일 parity(직교축).
  3. 진단 `[RampWidth]` 로그 4개 전부 제거(임시였음).
- 쐐기 폭은 `OJJ_BuildWedgeVisual(R, Cols, …)`로 Cols 경유 → 자동 정합. 세이브 스키마 변경 불필요(Size/RotationSteps 이미 저장).

## 이슈 목록
### ✅ codex 교차검증 — 실제 버그 없음 (5/5 확인)
1. Cols parity가 climb축과 정확히 직교 — Step 0/1/2/3 모두 커버(`ApplySaveState:393-396` ↔ 수정 `:530`).
2. 배치 직후 회귀 0 — CDO 정사각 (8,8)이라 `.X`/`.Y` 동일.
3. Step 이동 순서 문제 없음 — `OJJ_BuildWedgeVisual(R,Cols,Rise,CellSize,Step)` 호출 그대로, 중간 사용 없음.
4. `PlacedClimbLengthCells==0`(에디터 프리뷰/OnConstruction) 경로 — Step=0 → `Cols=FoundationSize.Y`로 기존과 동일.
5. 비주얼 폭 = 그리드 점유 일치 — `OJJ_BuildPerCellSurfaceZ`(even=X-climb/odd=Y-climb)와 Cols 직교축 정합.

## 조사 경위 (정정 이력)
