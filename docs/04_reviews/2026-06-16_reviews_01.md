> 컨베이어 raw-terrain 지형추종 + 공유상수 `OJJ_MaxSlopeStepZ` 이관 (이슈 #249)
> 성격: **착수 전(pre-implementation) 회귀 위험 리뷰** — Codex 교차검증 + Claude 검증. 코드 변경 없음.

## 변경 요약 (예정 작업 스코프)

이슈 #249는 컨베이어를 파이프처럼 **raw-terrain(GroundZ) 지형추종**시키고, 경사 게이트 상수를
파이프와 공유(`OJJ_MaxSlopeStepZ`)하는 작업이다. 본 리뷰는 착수 **전** 기존 코드(F3.7~F3.10
램프/Foundation 서브시스템)에 대한 회귀 위험을 평가하고 설계 분기점을 확정한다.

확정된 설계 결정(사용자 승인):
1. **상수 정책** — raw-terrain 신규 경로에만 `OJJ_MaxSlopeStepZ`(300) 참조. Foundation/램프 경로는
   `OJJ_MaxConveyorStepZ`(100) 유지. (통합 아님 → 램프 `MaxRampStepPerRow=100` 모순 회피)
2. **경로 정책**
   - raw-terrain 경사: buildable이든 가파른 자연 둑(blocked의 경사, 물가 ~208uu 등)이든 GroundZ를
     따라 통과. 단 raw 게이트(인접 셀 |ΔZ| ≤ 300) 내일 것.
   - **water 셀 거부 유지** (`bAllowWaterCells=false`). 컨베이어는 물 위로 가지 않음.
   - **혼합 경로(지형↔Foundation 전환)는 이번 패스 거부**. 이번 패스는 all-raw 경로만.
   - raw 경로는 **유효 GroundZ 필수** — 평면(plane) 폴백 금지 (Codex Q5).

## 핵심 검증 결과

### ✅ water ⊄ blocked (사용자 확인 요청 항목) — 안전 확인
- `OJJ_Grid.cpp:903` `IsCellBlocked` = `UnbuildableCells.Contains` — `:905` 주석 명시 "void·water와 **배타 집합**".
- `OJJ_Grid.cpp:898` `IsCellWater` = `WaterCells` (별도 집합).
- 결론: `bAllowBlockedCells=true`로 열어도 water 셀은 `IsCellBlocked=false`라 통과하지 않음. 게이트(`OJJ_Grid.cpp:433`)
  셀별 검증 시 water 셀은 `bAllowWaterCells=false`와 결합해 정확히 거부됨. **추가 분리 코드 불필요.**

## 이슈 목록 (회귀 위험)

### 🔴 Blocker / High 결합 — 반드시 보존
1. **`GetFoundationSurfaceZ` 장부 의미 불변** — `OJJ_Grid.cpp:1981`
   - 내용: 장부 Z는 점유/스택/배치 게이트의 공유 진실원. 비주얼 램프 면 Z(`:352`)와 의도적 분리.
   - 영향: raw-terrain 추종이 이 장부값을 비주얼 면 Z로 전역 대체하면 스택·폰 리프트·점유 전부 깨짐.
   - 제안: raw-terrain은 **별도 폴백 분기**로만. 장부 경로 무변경.
2. **`OJJ_GetUniformSurfaceZ` 의미 불변** — `OJJ_Grid.cpp:1993`
   - 내용: 머신 배치·Foundation 스택이 공유. 혼합 footprint 거부가 load-bearing.
   - 영향: 컨베이어 위해 이 헬퍼 의미를 바꾸면 스택 규칙 회귀.
   - 제안: 헬퍼 무변경, 컨베이어 raw 경로는 신규 헬퍼/분기 사용.
3. **램프 auto-fit 100uu vs 신규 300uu 모순** — `OJJ_RampFoundation.h:76`
   - 내용: 램프 건설은 `MaxRampStepPerRow=100` 가정. 컨베이어 한계를 일괄 300으로 올리면 어긋남.
   - 영향: 램프 위 컨베이어가 100 초과 단차를 무음 허용 → F3.10 램프 계약 위반.
   - 제안: **상수 분리 유지** (결정 #1로 채택). Foundation/램프 경로는 100 그대로.
4. **컨베이어 validator의 Foundation 전제** — `OJJ_Grid.cpp:311`
   - 내용: `OJJ_ValidateConveyorSlopePath`가 전 셀 `GetFoundationSurfaceZ` 요구.
   - 영향: raw-terrain 허용 시 이 전제를 깨야 함 — 암묵 우회는 Foundation 경로 회귀 유발.
   - 제안: raw-terrain **폴백 분기 신설**, 기존 Foundation 분기 무변경. 혼합 경로는 거부(결정 #2).

### 🟠 Major
5. **기준(base) Z 정책** — `OJJ_Grid.cpp:3510`
   - 내용: 현재 액터 기준 Z를 첫 노드에서 선택. raw-terrain 경사에선 음수 로컬 노드 Z 위험.
   - 제안: 파이프 패턴(min surface Z, `OJJ_Grid.cpp:2484`/`:2624`) 채택.
6. **raw-terrain 노드 Z 샘플링 API 부재** — `OJJ_Grid.cpp:3502`
   - 내용: 램프는 `OJJ_GetVisualSurfaceZAtWorld` 면 훅 샘플. raw terrain엔 등가 면 보간 API 없음.
   - 제안: `OJJ_GetPipeCellSurfaceZ`(`:937`) 류 셀별 GroundZ 추종을 컨베이어 노드 Z 소스로. plane 폴백 금지(결정 #2).
7. **아이템 Z 보간 인덱스** — `Conveyor.cpp:251`
   - 내용: `PathCells.IndexOfByKey`가 중복/끝점 셀에서 잘못된 인덱스를 읽을 여지.
   - 제안: 노드 Z 주입 후 중복 셀 시나리오 검증.

### 🟡 Minor / ⚪ Nit
8. **호버 프리뷰 Z 정렬** — `OJJ_Grid.cpp:3528` (`OJJ_GetCellVisualBaseZ`, 커밋 노드 Z와 불일치 가능) — #249에 프리뷰 포함 여부 결정 필요.
9. **Foundation 등록 포맷** — `OJJ_BuildController.cpp:1257` `OJJ_BuildPerCellSurfaceZ` 포맷 변경 금지.
