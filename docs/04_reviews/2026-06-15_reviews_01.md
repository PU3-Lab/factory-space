# 리뷰: 물질 이름·희귀도·속성·상태 결정론화 설계/계획

- 날짜: 2026-06-15
- 리뷰 대상: 설계 문서 [`docs/02_work_plans/material_name_rarity_state_design.md`](../02_work_plans/material_name_rarity_state_design.md), 구현 계획 [`docs/02_work_plans/material_name_rarity_state_plan.md`](../02_work_plans/material_name_rarity_state_plan.md)
- 성격: 구현 전 설계/계획 리뷰 (아직 코드 변경 없음, 브랜치 `feat/material-name-rarity-state`)

## 변경 요약

신물질 생성의 속성·category·state·희귀도를 LLM 자율에서 **입력 재료 기반 결정론 산출**로 전환하고, `material_hash`를 합성 정체성(장비+입력+공정) 기반으로 재정의한다. LLM은 이름·설명만 담당하며, 이름은 화학물질 스타일 가이드 + 규칙 검증을 거친다. 신규 모듈 `material_properties.py`/`derivation.py`와 `state` 필드(+plasma)·마이그레이션을 추가한다.

## 이슈 목록

### 🟠 Major

**M1. plasma 상태가 현재 속성 테이블로 도달 불가능 (dead state)**
- 위치: `material_name_rarity_state_design.md:§4.5`, `material_name_rarity_state_plan.md:Task 5`
- 내용: plasma 조건은 `reactivity ≥ 9 AND stability ≤ 1`. 그러나 기초 재료 16종의 **stability 최솟값은 3**(sulfur·wood). 가장 극단 조합(sulfur 단독 + high temp −1 + catalyst)으로도 `stability=2, reactivity=10`에 그쳐 `stability ≤ 1`을 만족할 수 없다. (수치 검증 완료)
- 영향: plasma는 절대 산출되지 않는 죽은 분기. "극단 합성의 희소 보상"이라는 의도가 구현되지 않음.
- 제안: 다음 중 하나.
  1. **(권장)** plasma 조건을 `reactivity ≥ 9 AND stability ≤ 2`로 완화 → sulfur 극단 조합(stability 2, reactivity 10)이 plasma 도달. gas(`stab≤3`)와 구분 유지됨.
  2. 또는 stability가 매우 낮은 기초 재료(예: 가스성 원료)를 테이블에 추가.
  3. 또는 plasma를 공정 조건(초고온 등 별도 플래그)에 직접 연동.

**M2. material_hash 합성 정체성화로 "서로 다른 레시피 → 동일 물질" 중복 제거가 불가능해짐 — dedup 분기 사실상 사문화**
- 위치: `material_name_rarity_state_design.md:§4.7`, `plan.md:Task 10/13`
- 내용: 기존 `material_hash`는 속성 기반이라 다른 레시피라도 속성이 같으면 동일 물질로 dedup됐다. 재정의 후 hash가 (장비+입력+공정)과 1:1이 되면서, 동일 합성은 이미 상위 `experiment_hash` 캐시(`lookup_cache_node`)에서 차단된다. 결과적으로 `deduplicate_material_node`의 `existing_mat` 분기는 도달 경로가 거의 없는 사문화 코드가 된다.
- 영향: 설계 의도(같은 입력→중복 방지)는 충족되나, "다른 경로로 같은 물질 발견 시 통합"이라는 기존 기능은 상실. dedup 노드가 혼란을 줄 수 있음.
- 제안: 의도가 맞다면(사용자 결정 사항) 수용하되, `deduplicate_material_node`의 잔존 분기를 단순화하거나 주석으로 "synthesis-identity 기준, experiment 캐시가 1차 방어선"임을 명시. 통합 기능이 필요하면 hash에 속성도 병기하는 2차 키를 고려.

### 🟡 Minor

**m1. LLM 프롬프트가 override될 구조화 값(properties/category/rarity)을 여전히 요구**
- 위치: `proposal_generator.py:_build_prompt`(기존), `plan.md:Task 12`
- 내용: 구조화 값은 derivation으로 덮어쓰는데 프롬프트는 여전히 해당 JSON 필드 생성을 지시. 토큰 낭비 + LLM 혼선 가능.
- 제안: 프롬프트를 이름·설명·risks·usage·visual_prompt 중심으로 슬림화(후속 정리 항목으로 둬도 무방).

**m2. 금지어 "test" 부분 문자열 전역 치환 위험**
- 위치: `result_validator.py:FORBIDDEN_KEYWORDS`(기존 유지), `plan.md:Task 11`
- 내용: `re.sub("test", ...)`/`replace("test", ...)`는 `latest`, `protest` 등 합법 단어 내부도 치환. 기존 동작을 답습하나 결정론 이름 품질에 영향.
- 제안: 단어 경계(`\btest\b`) 또는 정확 토큰 매칭으로 한정.

**m3. 단일 금속 입력의 category가 "alloy"로 산출 (의미 약함)**
- 위치: `derivation.py:derive_category`, `plan.md:Task 4`
- 내용: 합금(alloy)은 2종 이상 금속의 혼합인데, 단일 금속도 `not nonmetals → alloy`로 분류됨.
- 제안: 단일 입력 시 `metal`/`element` 등 별도 처리 고려(게임 표현상 허용 가능하면 보류).

### ⚪ Nit

**n1. `_ore` 접미사가 기초 원소와 동일 속성으로 취급**
- 위치: `material_properties.py:base_key`
- 내용: `iron_ore`가 `iron`과 같은 속성. 광석은 일반적으로 합성 입력이 아니지만, `base_key`가 동일화함. 의도치 않은 입력 허용 가능.
- 제안: 합성 입력 검증(prevalidator)과의 정합성 확인.

**n2. 현재 데이터 기준 실효 최고 상태는 gas**
- M1과 연결. plasma 수정 전까지 게임 내 최상위 상태는 gas임을 인지.

## 긍정적인 부분

- TDD 바이트사이즈 분해가 일관되고, 희귀도/상태 **경계값 테스트**를 명시해 회귀 안전성이 높음.
- 결정론화로 cross-run 재현성과 `material_hash` 안정성을 확보한 점이 설계 목표에 정확히 부합.
- `material_properties`(데이터)와 `derivation`(로직) 분리가 단일 책임 원칙에 잘 맞고, 속성 테이블이 실제 화학 특성에 근거해 튜닝 여지가 명확함.
- float 경계(8.5/7.0)가 정확히 표현됨을 수치 검증하여 테스트 취약성 우려를 사전 제거.
