# 코드 리뷰 — 포트레이트 캡처: 텍스처 스트리밍 완료까지 대기

**일자:** 2026-06-29 · **리뷰어:** Codex (codex-rescue, read-only) · **대상:** 커밋 전 워킹트리 C++ diff

## 변경 요약

셰이더 컴파일 대기(reviews_02)만으로는 첫 캡처가 **저해상도**로 찍히는 문제가 남았다. 진단 로그로 캡처 직전 로봇 텍스처 4장이 모두 **resident 7 / total 12 mips (NOT FULLY RESIDENT)** 임을 확인 — 텍스처 mip 스트림인이 미완. (텍스처 스트리밍은 패키징 런타임에도 발생 → 에디터 전용 아님)

- `CacheAndForceRobotTextures()`(BeginPlay): 로봇 머티리얼 텍스처 수집 → 각 `UTexture2D->bForceMiplevelsToBeResident=true`(격리 배치라 화면커버리지 스트리밍이 저밉에서 멈추는 것 방지) → `RobotTextures` 캐시.
- `TryBeginCapture()`: `IsCompiling()`(에디터) **AND** `AreRobotTexturesFullyResident()`(공통, 가드 없음) — 둘 다 충족 시 캡처. `CaptureMaxWarmupWait`(15s) 타임아웃 공유.
- 빌드 **Succeeded**, **PIE: 첫 PIE부터 풀해상도 캡처(통과), 타임아웃 경고 없음.**

## 이슈 목록

### 🟠→해결 Major — `bForceMiplevelsToBeResident` 수명 미복원 (리뷰 후 반영)
- **위치:** `Source/Wanted_Factory/Private/OJJ_PortraitCapture.cpp` `CacheAndForceRobotTextures`
- **내용:** force 플래그를 true로 설정 후 복원하지 않아, 액터(Subsystem `Deinitialize`가 `Destroy()`)가 사라진 뒤에도 공유 `UTexture2D`에 강제 풀밉이 영구 잔존. 메모리 비용이 액터 수명으로 제한되지 않음.
- **조치:** **반영 완료** — `CacheAndForceRobotTextures`에서 각 텍스처의 **원래 값을 `RobotTexturesPrevForceResident`에 저장**, `EndPlay`에서 **원본값으로 복원**(blind false가 아니라 원복 → 타 시스템이 force하던 텍스처 보존). 복원 후 캐시 Reset.

### 🟡→해결 Minor — 빈 캐시 시 무음 스킵 (리뷰 후 반영)
- **내용:** `RobotMesh` 없음/텍스처 0개 수집 시 `AreRobotTexturesFullyResident()`가 true 반환 → 대기를 건너뛰어 저해상도 첫 캡처가 조용히 재발 가능.
- **조치:** **반영 완료** — `RobotMesh` 없음, 텍스처 0개 수집 각각에 Warning 로그 추가("텍스처 없음"과 "수집 실패" 구분).

### 🟡 Minor — 전 텍스처(노멀/러프니스/메탈릭 포함) 대기 (수용)
- **내용:** `GetUsedTextures()`로 수집한 모든 텍스처의 full residency를 기다림 → portrait 품질 기여 작은 채널까지 대기/메모리 고정.
- **결정:** **수용**. 4장 규모 + PIE 검증 통과. 노멀/러프니스/메탈릭도 포트레이트 품질에 기여하므로 전부 대기가 타당. 지연 민감해지면 base color로 범위 축소 검토.

## 점검 항목 (Clean)

- `RobotTextures`를 `UPROPERTY(Transient)`로 둠 — 액터 생존 중 GC 안전. ✅
- 텍스처 스트리밍 대기를 `WITH_EDITOR` 밖에 둠 — 패키징 런타임까지 고려한 의도와 일치. ✅
- 빈 캐시 graceful degrade(true 반환) — 로그 보강으로 무음 재발 방지. ✅
