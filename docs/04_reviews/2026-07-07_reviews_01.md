## Issues

### 🟠 Major: Overly Broad Exception Handling in subprocess

**File:** `backend/src/tts/audio_postprocess.py:62–73`

**Issue:**  
Only `FileNotFoundError` and `subprocess.TimeoutExpired` are explicitly caught. Other `OSError` subclasses that could be raised by `subprocess.run` (e.g., `PermissionError` on pipe access, `BrokenPipeError` if a pipe closes unexpectedly) are not caught and would propagate uncaught, causing `synthesize_for_payload` to fail.

**Concrete Failure Mode:**  
If `ffmpeg` pipes become unavailable due to OS resource constraints or permission issues, a `PermissionError` or `BrokenPipeError` (both `OSError` subclasses) would crash the TTS synthesis rather than falling back to unprocessed audio.

**Example:**
```python
# Current code (lines 62–73):
try:
    result = subprocess.run(...)
except FileNotFoundError as exc:
    raise AudioPostprocessError(...) from exc
except subprocess.TimeoutExpired as exc:
    raise AudioPostprocessError(...) from exc
# PermissionError, BrokenPipeError NOT caught → unhandled exception
```

**Fix:**  
Catch `OSError` to cover all subprocess pipe-related errors:
```python
try:
    result = subprocess.run(...)
except (FileNotFoundError, subprocess.TimeoutExpired, OSError) as exc:
    raise AudioPostprocessError(f"ffmpeg 실행 중 오류 발생: {exc}") from exc
```

**Impact:** Major — the fail-open design goal is not fully achieved.

---

### 🟡 Minor: Inconsistent Timeout Between TTS and Post-Processing

**File:** `backend/src/tts/service.py:122`

**Issue:**  
The robotic effect post-processing uses a hardcoded 5-second timeout (`DEFAULT_TIMEOUT_SECONDS`), but TTS synthesis itself is limited to `self.settings.timeout_seconds` (default 2.0 seconds, configurable). This creates an asymmetry: post-processing can take up to 2.5× longer than the upstream synthesis.

**Code:**
```python
# Line 122 - no timeout parameter passed
audio_bytes = apply_robotic_effect(audio_bytes)
# Uses DEFAULT_TIMEOUT_SECONDS = 5.0 from audio_postprocess.py:20
```

**Expected behavior:**  
Post-processing should respect the same timeout budget as TTS synthesis for consistency.

**Fix:**  
Pass the timeout from settings:
```python
audio_bytes = apply_robotic_effect(
    audio_bytes, timeout_seconds=self.settings.timeout_seconds
)
```

**Impact:** Minor — only affects timeout behavior under load; fallback to unprocessed audio still works.
