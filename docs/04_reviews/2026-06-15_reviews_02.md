## 변경 요약

1차 리뷰의 6개 지적(M1·M2·m1·m2·m3·n1)에 대한 조치가 코드에 반영됐다. 대부분 정상 반영됐으나, **m2 조치가 새로운 회귀를 유발**했고 기존 테스트가 이를 잡지 못한다.

## 검증 결과

### ✅ 정상 반영 확인

- **M1 (plasma 도달 불가)** — `derive_state`가 `reactivity >= 9.0 and stability <= 2.0`으로 완화됨(`derivation.py:134`). 실제 실행 검증: `sulfur_powder` + `high temp` + `catalyst` → `state=plasma` (stability 2.0, reactivity 10.0). **진짜로 도달 가능해짐.**
- **M2 (dedup 사문화)** — `deduplicate_material_node`에 "lookup_cache가 1차 방어선, 본 노드는 안전장치(fallback)"임을 명시하는 주석 추가 확인(`nodes.py:409-412`). 의도 명문화 적절.
- **m3 (단일 금속 alloy)** — alloy 유지 결정. 수용.
- **n1 (`_ore` 동일화)** — prevalidator 차단 전제로 유지. 수용.

## 이슈 목록

### 🟠 Major

**M3(신규). m2 조치(`\b` 단어 경계)가 금지어 필터를 지배적 케이스에서 무력화 — 회귀**
- 위치: `result_validator.py:46`, `result_validator.py:67`
- 내용: 금지어 치환을 `re.sub(r"\b"+term+r"\b", ...)`로 바꿨는데, Python 정규식에서 **언더스코어(`_`)와 한글은 단어 문자(`\w`)** 라서 그 경계에 `\b`가 생기지 않는다. 실제 실행값으로 확인:
  - `_sanitize_id_hint("test_metal")` → **`"test_metal"`** (금지어 `test` 잔존)
  - `_sanitize_id_hint("dummy_alloy")` → **`"dummy_alloy"`** (금지어 `dummy` 잔존)
  - `_sanitize_name("합금test정")` → **`"합금test정"`** (한글에 붙은 `test` 잔존)
- 영향: id_hint는 **항상 언더스코어로 결합**되는 형식(`alloy_iron_copper`)이고, 이름은 **한글이 글자끼리 붙는다.** 즉 금지어 필터가 가장 흔히 마주치는 입력 형태에서 거의 작동하지 않는다. m2가 막으려던 부작용(`latest`/`protest` 훼손)은 고쳤지만, 본래 기능(비속어·junk 제거)을 더 크게 잃었다.
- 제안: `\b` 대신 **ASCII 알파벳 인접만 보호**하는 룩어라운드를 사용한다.
  ```python
  pattern = r"(?<![A-Za-z])" + re.escape(term) + r"(?![A-Za-z])"
  ```
  검증: `latest`/`protest`는 보존(앞뒤가 ASCII 알파벳), `test_metal`·`합금test정`·`alloy-Test`는 정상 치환. (`re.escape`도 함께 도입 권장.)

### 🟡 Minor

**m4(신규). 위 회귀에 대한 테스트 공백 — 63개 통과가 거짓 안심**
- 위치: `test_result_validator.py:46-109`
- 내용: 금지어 테스트 입력이 모두 **공백/하이픈 구분**(`"Invalid Trash 합금"`, `"alloy-Test!! Dummy"`)이라 `\b`가 우연히 작동하는 경우만 검증한다. 언더스코어 결합 id_hint나 한글 인접 금지어 케이스가 없어, M3 회귀를 스위트가 통과시킨다.
- 제안: `_sanitize_id_hint("dummy_alloy")`, `_sanitize_name("철test합금")` 등 회귀 케이스를 테스트에 추가.

**m1(재지적). 프롬프트 더미 가이드는 목표(부하 감소)를 달성하지 못함**
- 위치: `proposal_generator.py:99`
- 내용: override될 `properties/category/rarity`에 대해 "더미 문자열을 채워 반환하라"는 지시를 **추가**했다. JSON 스키마 블록은 그대로 남아 있어 프롬프트가 오히려 길어졌고, LLM에 무의미한 출력을 요구한다. 1차 리뷰의 취지(토큰·혼선 감소)와 반대 방향.
- 제안: 해당 필드를 프롬프트 JSON 예시·지시에서 제거하고, `MaterialProposalResult`에서 `category`/`rarity`에 기본값을 부여해 LLM이 생성하지 않아도 파싱되게 한다. (이름·설명·risks·usage·visual_prompt만 요청)

## 우선순위 권고

1. **M3 (금지어 필터 회귀)** — 머지 전 반드시 수정. 룩어라운드 패턴으로 교체.
2. **m4** — M3 수정과 함께 회귀 테스트 추가(둘은 한 묶음).

## 긍정적인 부분

- M1 수정이 단순·정확하며, 실제 산출 경로(sulfur 극단 합성→plasma)를 실행으로 재현해 검증 가능.
- M2 의도 명문화 주석이 후속 유지보수자에게 dedup 노드의 위상을 분명히 전달.
- derivation 모듈의 docstring이 공식·구간을 상세히 문서화해 가독성이 높음.
- 전체 결정론화 골격은 견고하며, 남은 이슈는 모두 이름/id 새니타이징이라는 좁은 표면에 국한됨.
