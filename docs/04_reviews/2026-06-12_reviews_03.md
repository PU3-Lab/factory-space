## 3. 잔여/신규 발견 사항

심각도: 🔴 Blocker · 🟠 Major · 🟡 Minor · ⚪ Nit

### 🟡 R1. `save_experiment`의 IntegrityError fallback이 실제 동시성 레이스를 해결하지 못함

- 위치: `backend/src/agents/material_generation/registry/experiment_registry.py:36-44`
- 내용: 동시 요청 충돌은 `experiment_hash`(unique)에서 발생하는데, fallback의 `session.merge(experiment)`는 **기본키 `id`(랜덤 uuid) 기준**으로 매칭한다. 충돌 행과 `id`가 다르므로 merge는 기존 행을 못 찾고 동일 `experiment_hash`로 재INSERT → 두 번째 `flush()`에서 IntegrityError가 **다시 발생하지만 이번엔 캐치되지 않아** 상위로 전파된다.
- 영향: savepoint 도입으로 외부 트랜잭션 오염은 막았으나, 진짜 "동시 동일 실험" 케이스는 여전히 `SYNTHESIS_ERROR`로 떨어진다(캐시 반환 graceful degrade 실패).
- 제안: IntegrityError 시 merge 대신 **`experiment_hash`로 재조회**하여 기존 실험을 반환하거나, dialect별 upsert(`on_conflict_do_nothing`/`INSERT OR IGNORE`) 후 재조회.

### 🟡 R2. `find_similar_experiments` 여전히 전체 결과 로드 후 파이썬 필터

- 위치: `backend/src/agents/material_generation/similarity.py:37-84`
- 내용: `machine_type` + `result_type="new_material"`인 모든 실험을 로드해 파이썬에서 overlap 계산/정렬하고 마지막에 `[:limit]`만 자른다. 쿼리 자체에는 입력 item_id 필터나 LIMIT가 없다.
- 제안: 입력 item_id 기반 DB 측 사전 필터 또는 정규화된 (experiment_id, item_id) 인덱스 테이블 도입.

### ⚪ R3. `db/models.py`의 pgvector 결합 (1차 D1 유지)

- 위치: `backend/src/db/models.py:21,27`
- 내용: 신규 `Base`가 `rag_schema`의 pgvector 기반 `metadata`를 공유한다. 마이그레이션 스모크 테스트로 SQLite 동작은 확인됐으나(embedding을 JSON 텍스트로 저장), `db.models` 임포트가 여전히 `pgvector` 설치를 강제하는 결합은 남아 있다.
- 제안: 신규 도메인 전용 `MetaData`/`DeclarativeBase` 분리 검토(선택).

## 4. 우선순위 권고

1. **R1** — 동시성 안전성 마무리(merge → 재조회/upsert). 나머지 블로커/메이저는 모두 해소됨.
2. **R2** — 데이터 누적 시 성능 저하 방지(현 단계에선 영향 낮음).
3. **R3** — 구조 정리(선택).

## 5. 총평
