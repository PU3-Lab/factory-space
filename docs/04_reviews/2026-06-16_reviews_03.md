## 이슈 목록

### 🔴 Blocker

**[R-1] `target_amount = shortage_amount`(델타)와 스냅샷 절대값 비교의 baseline 불일치 — 지원 퀘스트가 다시 메인을 채우지 못함**
- 위치: `2026-06-16-quest-agent-mvp-plan.md:132` (`target_amount = shortage_amount`) vs `:156-159` (완료 = `current_total >= target_amount`)
- 내용: `shortage_amount`는 델타(메인 required 20, current 8 → 12)인데, B-1 조치로 완료 판정이 절대 보유량(`current_total`)과의 비교로 바뀌었다. 두 값의 기준(baseline)이 다르다.
- 영향: 보유량이 12에 도달하면 지원 퀘스트가 완료되나 메인은 20이 필요하므로 여전히 8개 부족하다. B-1이 해결하려던 "지원 완료 = 메인 목표 정렬"이 baseline 불일치로 재차 깨진다(이슈 1의 본질적 재발).
- 제안: 절대 보유 목표로 통일 — `target_amount = 메인 required`(예: 20), 완료 `current_total >= 메인 required`. 델타 의미를 유지하려면 생성 시점 보유량(baseline)을 저장하여 `current_total - baseline >= shortage_amount`로 판정.
- **조치 결과 (Resolved)**: 제안에 따라 절대 보유 목표를 통일하기 위해 `target_amount`를 메인의 `required` 수량으로 정렬하여 계획서 Phase 3를 수정했습니다.

### 🟡 Minor

**[R-2] N-2는 "Resolved"로 표기됐으나 계획서에 미반영 (표기-실제 불일치)**
- 위치: reviews_02 `:58` (조치 결과) vs `2026-06-16-quest-agent-mvp-plan.md:37`, `:126`
- 내용: 조치 결과는 메인 목표 id를 `main_objective_id`로 변경하고 `KnownIssue`/`MainQuestObjective` 모델을 갱신했다고 기술하나, 계획서 `0.1-#8`(:37)과 Phase 2(:126)의 `known_issues` 구조는 여전히 `{item_id, shortage_amount, main_objective_id, producible}` — `main_objective_id` 그대로다.
- 영향: 네임스페이스 충돌(메인 목표 id vs 지원 목표 id 동명) 미해소. "Resolved" 신뢰성 저하.
- 제안: 계획서 :37, :126의 `objective_id` → `main_objective_id`로 실제 수정.
- **조치 결과 (Resolved)**: 계획서의 0.1-#8 절 및 Phase 2의 `known_issues` 구조 기술에서 `objective_id`를 `main_objective_id`로 실제 수정하였습니다.

### ⚪ Nit

**[R-3] MVP 수용 기준이 B-1 조치와 모순 (잔존 표현)**
- 위치: `2026-06-16-quest-agent-mvp-plan.md:177`
- 내용: 수용 기준이 "`item_collected`로 진행도 누적(동일 event_id 멱등)"으로 남아 있으나, B-1 조치 후 Phase 6은 누적이 아닌 대입(`current_amount = current_total`)이다.
- 영향: 테스트 설계 시 혼동(누적 vs 대입).
- 제안: ":177"을 "보유량 스냅샷 대입 → target 도달 시 completed"로 수정.
- **조치 결과 (Resolved)**: 계획서 :177 라인의 MVP 수용 기준 문구를 "보유량 스냅샷 대입(current_amount = current_total) -> target 도달 시 completed"로 변경했습니다.

**[R-4] §3.2 Pydantic 모델 기술이 조치 주장과 불일치**
- 위치: `2026-06-16-quest-agent-mvp-plan.md:108-111`
- 내용: B-2/N-2 조치 결과는 `QuestObjective.id`, `KnownIssue`, `MainQuestObjective` 모델 변경을 주장하나, §3.2는 여전히 일반 모델 목록(`QuestContext`, `QuestObjective`, `QuestReward`, `SupportQuestDraft`, `ValidationResult`)만 나열하여 해당 필드/모델이 추적되지 않는다.
- 제안: §3.2에 `KnownIssue`(`main_objective_id` 포함), `QuestObjective.id` 등 변경 필드를 명시.
- **조치 결과 (Resolved)**: 계획서의 §3.2 Pydantic 모델 목록에 `CurrentMainQuest`, `MainQuestObjective`, `KnownIssue`, `QuestInstance`, `QuestProgress`를 명시적으로 추가 기재했습니다.
