# 코드 리뷰 — 포트레이트 캡처: 셰이더 컴파일 완료까지 대기

**일자:** 2026-06-29 · **리뷰어:** Codex (codex-rescue, read-only) · **대상:** 커밋 전 워킹트리 C++ diff

## 변경 요약

A-1(고정 0.3초 지연)으로는 첫 프레임 글리치가 남았다. 원인은 에디터 첫 PIE 시 **M_Robot 베이스패스 셰이더가 DDC 미스로 컴파일 중**(셰이더당 ~0.42초, 콜드 시 수 초)이라 로봇이 디폴트 머티리얼로 깨진 채 캡처되는 것. 머티리얼 에디터를 한번 열면 셰이더가 동기 컴파일·캐시되어 정상화되던 증상이 이를 확증.

고정 지연 대신 **실제 셰이더 컴파일 완료를 폴링해 대기**하도록 변경:

- `BeginPlay` → `CaptureWarmupDelay`(0.3s, 폴 시작 전 초기 지연 — 컴파일 잡 큐 등록 대기) 후 `TryBeginCapture()` 스케줄.
- `TryBeginCapture()` — `#if WITH_EDITOR` 안에서 `GShaderCompilingManager->IsCompiling()`이 true이고 누적 대기 < `CaptureMaxWarmupWait`(15s)인 동안 `CaptureWarmupPollInterval`(0.15s) 간격 재폴링. 완료/타임아웃 시 `BeginContinuousCapture()`(`bCaptureEveryFrame=true` + `CaptureScene()`). 타임아웃 시 Warning.
- `#if WITH_EDITOR #include "ShaderCompiler.h"` — 패키징은 셰이더 쿡되어 대기 분기 통째 제외, 즉시 캡처.
- 빌드 `Wanted_FactoryEditor Win64 Development`: **Succeeded**. **PIE 검증: 첫 PIE부터 포트레이트 깨끗(통과).**

- **위치:** `Source/Wanted_Factory/Private/OJJ_PortraitCapture.cpp` (TryBeginCapture 폴링 타이머)
- **내용:** 워밍업 폴링 도중 액터가 파괴되면(`UOJJ_PortraitCaptureSubsystem::Deinitialize`가 자동 스폰분을 `Destroy()`) 보류 타이머 콜백이 파괴된 액터에 도달할 여지.
- **영향:** 좁은 윈도우(워밍업 0.3~수 초 사이 레벨 종료/전환)지만 실재.
