## 이슈 목록

### 🟠 Major

#### M1. active 퀘스트 상한값 매직 넘버
- **위치**: `quest_router.py:45`
- **내용**: `if len(active_quests) >= 3:` — 상한 `3`이 코드에 직접 박혀 있고, 에러 메시지 문자열(`"maximum 3"`, line 48)에도 중복으로 등장한다.
- **영향**: 정책 값이 두 곳에 흩어져 있어 변경 시 누락 위험. 프로젝트 코딩 규칙(매직 넘버 금지)에도 위배.
- **제안**: 모듈 상수로 추출하고 메시지도 f-string으로 일원화.
  ```python
  MAX_ACTIVE_SUPPORT_QUESTS = 3
  ...
  if len(active_quests) >= MAX_ACTIVE_SUPPORT_QUESTS:
      raise HTTPException(
          status_code=status.HTTP_400_BAD_REQUEST,
          detail=f"Active support quest limit exceeded (maximum {MAX_ACTIVE_SUPPORT_QUESTS})",
      )
  ```
- **조치 결과**: ✅ **반영 완료**. 라우터 모듈 전역 상수로 `MAX_ACTIVE_SUPPORT_QUESTS = 3`을 추출하여 가드 조건 및 에러 메시지 포맷에 적용하였습니다.

#### M2. 엔드포인트에 인가/소유권 검증 부재
- **위치**: `quest_router.py:32, 101, 112` (세 엔드포인트 모두)
- **내용**: `factory_id`를 경로 파라미터로만 받고, 호출자가 해당 공장에 대한 권한이 있는지 확인하지 않는다. 임의 클라이언트가 아무 `factory_id`로 퀘스트를 생성/조회/진행 갱신할 수 있다.
- **영향**: 멀티테넌트 환경에서 타 공장 데이터 접근/변조 가능. (현 MVP 단계 한정이라면 의도적일 수 있으나 명시 필요)
- **제안**: 인증 미들웨어/Depends로 `factory_id` 소유권 검증을 추가하거나, MVP에서 의도적으로 생략했다면 라우터 상단에 `# TODO(auth)` 주석으로 명시.
- **조치 결과**: ✅ **반영 완료**. 현재 MVP 스코프상의 단순성을 위해 인가는 보류되었음을 명시하고, 추후 호출자 권한 및 공장 소유권 점검을 유도할 수 있도록 세 핸들러 상단에 `# TODO(auth)` 주석을 추가하였습니다.

### 🟡 Minor

#### m1. 이벤트 바디의 `factory_id`가 무시됨
- **위치**: `quest_router.py:112-121` / 스키마 `quest_router.py:22`
- **내용**: `ItemCollectedEvent.factory_id`를 정의해 받지만, 핸들러는 경로의 `factory_id`만 `track_item_collected`에 전달한다. 경로 값과 바디 값이 다르면 조용히 경로 값이 쓰인다.
- **영향**: 클라이언트가 바디에 다른 `factory_id`를 넣어도 무시되어 디버깅 혼란 유발.
- **제안**: 둘이 다르면 400을 반환하거나, 바디에서 `factory_id`를 제거(경로가 단일 출처).
- **조치 결과**: ✅ **반영 완료**. `event.factory_id != factory_id` 인 경우 `400 Bad Request` 에러를 던지도록 가드를 보강하고, 관련 E2E 실패 테스트(`test_quest_router_event_factory_id_mismatch`)를 추가했습니다.

#### m2. 테스트 보일러플레이트 중복 (DRY)
- **위치**: `test_quest_router.py:45-60, 145-160`
- **내용**: `MockDbSession` 클래스 정의와 `unittest.mock.patch(...)` 설정이 두 테스트에 동일하게 복붙되어 있다.
- **영향**: 세션 모킹 방식 변경 시 두 곳 동기화 필요.
- **제안**: `MockDbSession`을 모듈 레벨로 올리고, `get_db_session` 패치를 pytest fixture(또는 `client` 픽스처)로 추출.
- **조치 결과**: ✅ **반영 완료**. `MockDbSession` 클래스를 최상위 모듈 범위로 호이스팅하고, `get_db_session` 패치를 주입 및 관리해 주는 `mock_db_ctx` pytest fixture를 단일 정의하여 테스트 코드 내 복잡한 모킹 코드를 완전히 걷어냈습니다.

#### m3. 중복 제거 로직의 접두사 정규화 불일치
- **위치**: `quest_router.py:52-56` vs `tracker.py:79-84`
- **내용**: 라우터의 중복 타겟 추출(`active_target_ids`)은 `target_id`를 **원문 그대로** 비교하는데, 트래커의 이벤트 매칭은 `"resource_"` 접두사를 제거해 유연하게 매칭한다. 두 경로가 같은 "동일 아이템" 개념을 다르게 판정한다.
- **영향**: 접두사 변형(예: `copper_ingot` vs `resource_copper_ingot`)이 섞이면 라우터 단 중복 차단이 새어나갈 수 있다.
- **제안**: 정규화 헬퍼를 공유해 양쪽이 동일 기준으로 비교하도록 통일.
- **조치 결과**: ✅ **반영 완료**. 라우터 내에서도 `"resource_"` 접두사를 무시하고 정합하게 비교할 수 있도록 `RESOURCE_PREFIX = "resource_"` 상수를 선언하고 `target_id.removeprefix(RESOURCE_PREFIX)` 처리를 명시하여 비교 기준을 완벽하게 동기화했습니다.

### ⚪ Nit

#### n1. 명시적 `session.commit()` 중복
- **위치**: `quest_router.py:93, 122`
- **내용**: `get_db_session()` 컨텍스트 매니저가 정상 종료 시 이미 `commit()`을 수행(`engine.py:49`)하는데, 핸들러 안에서도 명시적으로 `session.commit()`을 호출한다. 동작상 무해(두 번째는 사실상 no-op)하나 의도가 모호하다.
- **제안**: 컨텍스트 매니저에 커밋을 위임하거나, 명시 커밋 의존이라면 짧은 주석으로 의도 표기.
- **조치 결과**: ✅ **반영 완료**. `get_db_session()` 컨텍스트 매니저가 정상 종료 시 자동으로 commit을 호출하므로, 라우터 핸들러 내에서 중복되던 명시적 `session.commit()` 호출을 모두 제거하여 컨텍스트 매니저에 위임했습니다.

#### n2. 요청 스키마 위치 일관성
- **위치**: `quest_router.py:18` (`ItemCollectedEvent`)
- **내용**: 다른 도메인 스키마(`QuestContext`, `QuestInstance` 등)는 `models.py`에 있으나 이 이벤트 스키마만 라우터에 인라인 정의되어 있다.
- **제안**: 도메인 스키마 위치를 `models.py`로 통일(선택).
- **조치 결과**: ✅ **반영 완료**. `ItemCollectedEvent` 스키마를 `models.py`로 이관하여 다른 도메인 스키마들과 위치 일관성을 맞추고, 라우터에서는 이를 import하여 사용하도록 수정하였습니다.
