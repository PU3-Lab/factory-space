## 3. Phase 2 신규 이슈

### 🔴 Blocker

#### B1. 사용자별 절대 경로 하드코딩 — 다른 환경에서 데이터 로딩 실패
- **위치**: `backend/src/agents/quest_generator/game_data.py:31-35`
- **내용**: `data/game` 탐색 실패 시 fallback으로 특정 사용자 머신의 절대 경로를 하드코딩한다.
  ```python
  workspace_root = Path("/Users/kimkyungpyo/Workspaces/projests/factory-space")
  ```
  현재 레포에서는 `data/game`이 루트에 있어 상위 탐색이 성공하므로 이 분기가 dead path지만, 컨테이너/CI/타 개발자 환경처럼 작업 경로가 다르거나 데이터 위치가 바뀌면 이 경로로 폴백하며 즉시 깨진다.
- **영향**: 이식성·재현성 붕괴(CI/배포 환경에서 `FileNotFoundError`), 소스에 개인 경로·사용자명 노출. 전역 코딩 규칙("No hardcoded values") 및 보안 규칙("NEVER hardcode") 정면 위반.
- **제안**: 하드코딩 경로 제거. 프로젝트 루트는 환경변수(`GAME_DATA_DIR`) 또는 패키지 기준 상대 경로로 일원화하고, 미발견 시 명확한 에러로 실패시킨다.
  ```python
  data_dir = os.environ.get("GAME_DATA_DIR")
  # 또는 repo 루트 마커(pyproject.toml 등) 기준 탐색 후, 없으면 raise
  ```
- **조치 결과 (Resolved)**: 하드코딩된 절대 경로를 완전히 제거하고, `GAME_DATA_DIR` 환경 변수를 조회하는 로직을 추가했습니다. 환경 변수가 명시되어 있지 않은 상태에서도 기존의 상향 경로 탐색이 실패하면 `FileNotFoundError`를 명확히 발생시키도록 정돈했습니다.

### 🟠 Major

#### M-a. 전역 lazy 초기화의 동시성 안전성 부재
- **위치**: `backend/src/agents/quest_generator/game_data.py:9-17, 72`
- **내용**: `_init_game_data()`가 모듈 전역(`_initialized`, `_valid_item_ids`, `_recipe_map` …)을 락 없이 갱신한다. FastAPI 멀티스레드/동시 요청에서 두 호출이 경합하면 한 스레드가 절반만 채워진 전역을 읽을 수 있다.
- **영향**: 초기 워밍업 구간에서 간헐적 빈/부분 데이터로 잘못된 `producible` 판정·검증 통과 위험.
- **제안**: `threading.Lock`으로 임계구역 보호하거나, 앱 시작 시 1회 명시적 로드(예: lifespan startup)로 전환.
- **조치 결과 (Resolved)**: `threading.Lock` 객체(`_lock`)를 전역으로 선언하고, `_init_game_data()` 내부에서 임계구역 보호를 위해 이중 확인 잠금 패턴(Double-checked locking pattern)을 적용함으로써 멀티스레드/동시 요청 환경에서의 정합성을 보장했습니다.

### 🟡 Minor

#### m-a. ruff 린트 7건 미정돈 (CLAUDE.md 포맷 규칙 위반)
- **위치**: `backend/src/db/models.py:216,271`, `backend/tests/test_quest_context_builder.py:150-151,178`
- **내용**: `ruff check` 결과 `I001`(import 정렬) 2건, `ANN201`(`to_pydantic` 반환 타입 누락) 1건, `UP017`(`datetime.UTC` 권장) 1건 등 총 7건. 5건은 `--fix` 가능.
- **제안**: `ruff check --fix .` 및 `ruff format .` 실행. `to_pydantic`에 반환 타입 어노테이션(`-> "QuestInstance"` / `-> "QuestProgress"`) 명시.
- **조치 결과 (Resolved)**: `to_pydantic()` 함수들에 `QuestInstance` 및 `QuestProgress` 반환 타입 힌트(`-> QuestInstance`, `-> QuestProgress`)를 명확하게 적용하였으며, `ruff check --fix .` 포맷팅과 `ruff format .`을 실행하여 모든 린트 에러를 완전히 제거했습니다.

#### m-b. 단위 테스트가 실제 게임 CSV·한글 이름에 강결합
- **위치**: `backend/tests/test_quest_context_builder.py:9-28`
- **내용**: `test_game_data_loader`가 `resources.csv`/`recipes.csv`의 실제 내용("목재","철괴", `recipe_smelt_iron` 존재)에 의존한다. 게임 데이터가 바뀌면 로직 변경 없이도 단위 테스트가 깨진다.
- **제안**: 임시 CSV 픽스처(`tmp_path`)로 로더를 검증하거나, 해당 테스트를 통합 테스트(`@pytest.mark.integration`)로 분류.

#### m-c. 레시피 다중 산출물 정보 손실
- **위치**: `backend/src/agents/quest_generator/game_data.py:66-70`
- **내용**: `output_ids[0]`만 채택해 산출물이 여럿인 레시피의 나머지를 버린다. MVP 범위에서는 무방하나 향후 `producible` 판정 누락 가능.
- **제안**: 한계를 주석으로 명시하고, 다중 산출이 필요해지면 `output_ids` 전체를 보존하도록 자료구조 확장.

#### m-d. 외부 payload 수치 필드 사전 검증 부재
- **위치**: `backend/src/agents/quest_generator/context_builder.py:74-89`
- **내용**: 클라이언트(Unreal) payload의 `required`/`current`를 `MainQuestObjective` 생성(Pydantic 검증) 전에 그대로 `required > current`, `required - current` 산술에 사용. 비정상 타입/값 유입 시 조용히 잘못된 `shortage_amount` 생성 가능.
- **제안**: payload 자체를 입력 전용 Pydantic 모델로 1차 파싱하여 경계에서 검증 후 사용.

### ⚪ Nit

#### n-a. 빈 CSV 시 `next(reader)` StopIteration 미처리
- **위치**: `backend/src/agents/quest_generator/game_data.py:46,58`
- **내용**: 헤더 스킵용 `next(reader)`는 파일이 완전히 비면 `StopIteration`을 던진다.
- **제안**: `next(reader, None)` 사용 또는 빈 파일 가드.
- **조치 결과 (Resolved)**: `next(reader)` 호출 부분을 `next(reader, None)`으로 교체하여 빈 CSV 파일 로드 시의 `StopIteration` 예외 발생 가능성을 완벽히 가드했습니다.
