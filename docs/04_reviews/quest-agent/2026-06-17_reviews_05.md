- 대상 계획서: [docs/02_work_plans/2026-06-16-quest-agent-mvp-plan.md](../../02_work_plans/2026-06-16-quest-agent-mvp-plan.md)
- 성격: 코드 변경 없음. 누적 리뷰(B~Y 시리즈) 전체를 단일 인계 문서로 정리.

> 이 문서는 코딩 에이전트가 위 계획서를 그대로 구현하기 위한 **단일 진실(source of truth) 인계서**다.
> 이전 리뷰 체인(reviews_01~04)은 검증 이력일 뿐, 구현에 필요한 정보는 모두 본 문서에 통합되어 있다.

---

## 1. 한 줄 요약

클라이언트(Unreal)가 게임 상태를 payload로 보내고, 서버는 **지원 퀘스트 1종(`collect_item`)** 을 생성·검증·영속화하고 `item_collected` 이벤트로 진행도를 스냅샷 대입 추적한다. 서버는 게임 상태에 대해 stateless이며, **퀘스트 인스턴스/진행도만** 영속화한다.

## 2. 확정된 설계 결정 (재논의 불필요)

| ID | 결정 | 근거 |
|---|---|---|
| D-1 | 게임 상태는 **클라이언트 payload 신뢰**, 서버 stateless | 백엔드에 factory/인벤토리/메인퀘스트 영속화 없음 |
| D-2 | 1차 지원 타입 = **`collect_item`(보유량 달성)**, `produce_item` 아님 | 생산 완료가 메인 목표 진행을 보장 못 함 |
| D-3 | `target_amount = 메인 퀘스트 objective의 required 수량` | (a) 복제본 수용 — 정합성 최우선, snapshot 정렬 |
| D-4 | `shortage_amount`는 **description 생성에만 소비** | dead field 방지 |
| D-5 | item id 네임스페이스 = **`resource_*` 단일 진실** (`resources.csv`) | 기획서 예시 `iron_ingot` → `resource_iron_ingot` 매핑 |
| D-6 | `item_name` = `game_data` 로더가 `resources.csv`의 `자원명` 컬럼에서 `item_id`로 조회 | 한국어 자원명, description/title에 사용 |
| D-7 | 진행도 = **`current_amount = current_total` 스냅샷 대입** (멱등) | 이중 카운트 방지 |
| D-8 | `objective_id` = `obj_{uuid}` (인스턴스 비의존) | 오매칭 방지 |
| D-9 | active 지원 퀘스트 **상한 3개/factory** + 동일 아이템 재생성 차단 | 스팸 방지 |
| D-10 | 보상 = **소량 `currency`만**, 대상 아이템·레시피 입력재 제외 | 순환 파밍 방지 |

## 3. 빌드 순서 (Phase = 작업 단위, 순차 의존)

각 Phase는 TDD로 진행: 테스트 작성(RED) → 구현(GREEN) → 리팩터. 완료 조건(DoD)을 만족해야 다음 Phase 진입.

| Phase | 산출물 | DoD (완료 기준) |
|---|---|---|
| 1 | `models.py` Pydantic + `db/models.py` 2테이블 + `migrations/versions/0004_create_quest_tables.py` | `alembic upgrade head`(sqlite) 성공, 모델 import 테스트 통과 |
| 2 | `game_data.py` 로더 + `context_builder.py` | 기획서 5.3 예시 payload로 구조화 `known_issues` 계산 + id 매핑 단위 테스트 통과 |
| 3 | `rule_generator.py` (`collect_item` 초안) | 부족/중복 분기 + `objective_id` 독립성 단위 테스트 통과 |
| 4 | `validator.py` | 선행조건 skip/통과 케이스(입력재 미확보→skip, 원재료→통과) 단위 테스트 통과 |
| 5 | `repository.py` + `manager.py` + `reward_resolver.py` | 지급→저장→조회 통합 테스트(sqlite) + 보상 제외 단위 테스트 통과 |
| 6 | `progress_tracker.py` | 스냅샷 대입→완료 전이 + 동일 `event_id` 재전송 시 상태 불변 통합 테스트 통과 |
| 7 | `quest_router.py` + `app.py` include | TestClient E2E: compose-support → events ×N → GET 목록 completed 확인 |

모든 신규 파일 위치: `backend/src/agents/quest_generator/` (레퍼런스 패턴 = `material_generation` 모듈).

## 4. API 계약 (Phase 7)

| 메서드 · 경로 | 입력 | 출력 |
|---|---|---|
| `POST /api/v1/factories/{factory_id}/quests/compose-support` | QuestContext 원천 payload (메인퀘스트 objectives + inventory + unlocked_recipes + active_support_quest_ids) | 생성된 instance. active 상한(3) 초과·동일 아이템이면 거부 |
| `GET /api/v1/factories/{factory_id}/quests` | — | 퀘스트 목록 |
| `POST /api/v1/factories/{factory_id}/quests/events` | `item_collected`(`event_id`,`factory_id`,`item_id`,`current_total`) | 진행도 갱신 결과 (WS 푸시 대체) |

## 5. 가드레일 (구현 중 항상 준수)

- **불변성**: 객체 in-place 변경 금지, 새 객체 반환.
- **입력 검증**: Pydantic `extra="forbid"`로 payload 엄격 검증 (경계에서 fail-fast).
- **네임스페이스**: item id는 `resource_*`만. 검증 소스는 `resources.csv`.
- **포맷/린트**: 작성·수정 후 `ruff check --fix .` + `ruff format .` 실행 (프로젝트 규칙).
- **파일 크기**: 모듈당 200~400줄 목표, 800줄 상한. 큰 모듈은 분리.
- **테스트 커버리지**: 신규 코드 80% 이상.

## 6. 스코프 경계 (이번에 하지 말 것)

- 나머지 4종 퀘스트 타입, WS 서버 푸시, 공장 레벨 진행, LLM 문장 보강, 다중 목표 → **후속 단계**.
- 기존 하드코딩 프로토타입(`quest_generator/service.py`)은 **삭제하지 말 것** (MVP 검증 후 정리).

## 7. 잔여 리스크 (구현을 막지는 않음)

- 클라이언트 payload 신뢰 → 진행도/인벤토리 정합성 미보장 (MVP 허용).
- 레벨/메인퀘스트 서버 권위 충돌 → 본격 도입 시 선행 결정 필요 (현재 범위 밖).
- compose-support 호출 트리거(스케줄러/조건) 미정의 → MVP는 수동 호출 + active 상한으로만 제어.

## 8. 누적 리뷰 수렴 이력 (참고)

계획서는 8라운드 검증을 거쳐 본문 정합성이 유지됐다. 모든 추적 이슈(B/M/N/R/T/U/V/W/X 시리즈) 수렴 완료. 단 하나 남은 동형 Nit은 **본 문서로 종결**한다:

- **[Y-1 → 종결]** reviews_03 "우선순위 권고" 항목 2가 X-1 Resolved를 미반영하던 문서 일관성 Nit. 본 인계서가 단일 진실 문서가 되면서 메타-리뷰 체인의 우선순위 섹션 동기화 문제는 더 이상 추적 대상이 아니다. (구조적 원인: 이슈 본문 Resolved 추가 시 같은 파일 우선순위 섹션 미갱신 → V·W·X·Y 동형 반복. 향후 리뷰는 본문+우선순위를 동시 갱신할 것.)

## 9. 긍정적인 부분

- 계획서가 결정→Phase→검증을 라인 단위로 매핑해, 에이전트가 추론 없이 구현 가능한 수준의 명세를 갖췄다.
- `collect_item` 채택과 `target_amount` 스냅샷 정렬로 R-1/T-1 정합성 결함을 구조적으로 제거했다.
- `shortage_amount`를 description 소비처로 삼아 dead field와 템플릿 미정의(U-1/U-2)를 단일 편집으로 동시 해소했다.
