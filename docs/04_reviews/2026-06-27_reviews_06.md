# 코드 리뷰 — #7 램프 한쪽-이웃 "커서로 늘어남" 제거 (보행 슬로프 길이 고정)

- 날짜: 2026-06-27
- 리뷰 방식: 조사(자동맞춤 타이밍) → codex(GPT) 교차검증
- 영역: OJJ (OJJ_RampFoundation)

## 변경 요약

한쪽-이웃 하강 램프에서 마우스를 끌면 길이가 늘어나던 현상 제거. 길이를 커서거리와 무관하게 **보행 슬로프로 지면까지 = (WalkGap−1)칸 고정**.

- 원인: 한쪽-이웃 분기(`OJJ_ComputeHoverFootprint:189-254`)에서 `GapLength = DistNeg + DistPos − 1`(`:259`), 한쪽은 `DistFound`(커서~파운데이션). `DistGround = Max(1, WalkGap − DistFound)`(`:244`)의 `Max(1,..)` 클램프가 `DistFound ≥ WalkGap`(커서 멀때)에서 1로 깔려 `GapLength = DistFound`(커서거리)로 늘어남.
- 수정 (한 줄, `:244`): `DistGround = WalkGap − DistFound` (클램프 제거). `DistFound`가 상쇄돼 `GapLength = WalkGap−1`(커서 무관). `Origin = CursorCell−(DistNeg−1)`은 `DistFound`가 파운데이션을 추적하므로 **이미 파운데이션 변 앵커**(별도 수정 불필요).

## 이슈 목록

### ✅ codex 교차검증 — 길이 버그 수정 정확, 회귀 0
- `GapLength = WalkGap−1` 이 bNeg/bPos 양쪽 모두 커서 무관 성립(synth가 반대측 Dist를 채움 `:247-248`).
- 음수 `DistGround`(커서 멀때)는 `GapLength`에만 반영 — Origin(파운데이션 변 재정렬)/EffSize/방향(ZNeg·ZPos는 Z 비교)/`LoEndLowestGroundRaw` 스캔 불파괴.
- `WalkGap ≥ 4`(OneSideRiseSteps≥1, SnapStep=100, WalkLimit=45) → `GapLength ≥ 3` 보장.
- 양쪽-이웃(`bNeg && bPos`)은 본 분기(`bNeg != bPos`) 밖 → 회귀 0. 커서 가까울때(DistFound<WalkGap)는 기존 `Max` 미클램프라 동값.
- 검증(`:287 GapLength-1 < RequiredIntervals`)은 기본 `MaxRampStepPerRow=100`에서 통과(커서 가까울때 이미 그 길이라 동일 기준).

### 🟡 알려진 한계 (사전 존재·후속) — 높이 샘플의 커서 의존
- 위치: `OJJ_ComputeHoverFootprint:193` `GroundLineOrigin = CursorCell ± 1`.
- 내용: 길이/Origin은 커서 무관이 됐으나, 지면 높이(`DeltaReal`/`OneSideRiseSteps`/`SynthGroundZ`)는 여전히 **커서 옆 1칸 지형**에서 샘플. **경사 지형 + 커서가 파운데이션에서 먼** 경우 실제 램프 낮은끝이 아닌 커서 근처 지형으로 높이가 결정될 수 있음.
- 영향: **평탄 지형 무영향.** 경사 지형의 커서-원거리 케이스에서만 rise/길이 미세 오차.
- 조치: 이번 스코프(커서거리 길이 제거)는 충족. 엄밀한 "높이까지 커서 무관"은 **후속** — `DistGround` 산출 후 실제 낮은끝 바깥 라인에서 `GroundRawZ` 재샘플.
