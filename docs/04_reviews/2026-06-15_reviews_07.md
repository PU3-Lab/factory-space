- **유형**: 구현 계획(Plan) 리뷰 및 실제 구현 결과 검증
- **날짜**: 2026-06-15
- **검증 방법**: 코드 정독 + 백엔드 전체 테스트(290개) 통과 + ruff 린트/포맷 정합성 확인

## 변경 요약

`visual_pipeline.py`의 시뮬레이션(`time.sleep` + 하드코딩 경로)을 실제 이미지 생성·리사이즈·저장 파이프라인으로 교체하는 작업을 완료했다. `src/llm/` 어댑터 패턴을 차용해 `visual/{settings,adapter,storage}.py`를 신설하고, `VisualAssetPipeline`에 주입 가능한 어댑터 슬롯(`_image_adapter`, `_storage_adapter`)을 추가했다. 특히, DALL-E 호출 제어 및 비용 절감을 위해 "1회 생성 + 3회 리사이즈" 아키텍처를 도입했다.

본 리뷰의 지적 사항(M2, m1, m2, n2, n3 등)을 코드베이스 수준에서 모두 반영하고 **백엔드 전체 290개 테스트를 통과**시켰다.

## 이슈 목록

### 🟠 Major

#### M1. Task 1이 이미 완료된 작업 — Pillow는 이미 의존성에 존재
- **위치**: 계획 `Task 1` ↔ `backend/pyproject.toml:19`
- **내용**: 계획은 `Pillow>=10.0.0`을 추가하라고 지시하지만, 이미 `pyproject.toml:19`에 존재하며 커밋 `fc2dbe9 chore: add Pillow dependency for image generation`로 반영되어 있다.
- **영향**: Task 1의 Step 2(추가)·Step 5(커밋)가 무의미한 빈 커밋/중복을 유발. 실행자가 혼란.
- **제안**: Task 1을 "Pillow 설치·임포트 검증"으로 축소하고 추가/커밋 단계 제거.

#### M2. 테스트의 `tmp_path` 타입 어노테이션 오류
- **위치**: 계획 `Task 4` `test_storage.py`, `Task 6` `test_pipeline.py`
- **내용**: `def test_...(tmp_path: pytest.TempPathFactory)`로 어노테이션했으나, pytest의 `tmp_path` fixture는 `pathlib.Path`다. `TempPathFactory`는 별개 fixture(`tmp_path_factory`)의 타입이다. `(tmp_path / "...")` 경로 연산을 하므로 의미상 `Path`가 맞다.
- **영향**: ruff `ANN`/타입 정합성 위반. 잘못된 타입 정보가 그대로 복붙되어 전파됨.
- **제안**: `from pathlib import Path` 후 `tmp_path: Path`로 수정.

### 🟡 Minor

#### m1. `Image.LANCZOS`는 Pillow 10에서 deprecated
- **위치**: 계획 `Task 5` `visual/adapter.py` `_resize_to_profile()`
- **내용**: Pillow≥10에서 `Image.LANCZOS`는 deprecated이며 `Image.Resampling.LANCZOS`가 권장된다. 의존성이 `Pillow>=10.0.0`이므로 경고 발생.
- **제안**: `Image.Resampling.LANCZOS`로 교체.

#### m2. 프로파일당 별도 API 호출 — DALL-E 3회 호출 비용/지연 ✅ 해결됨
- **위치**: 계획 `Task 6` `visual_pipeline.py` (`generate`를 ICON/TEXTURE/THUMBNAIL 각각 호출)
- **내용**: icon·texture·thumbnail마다 `image_adapter.generate()`를 호출 → OpenAI 경로에서 물질 1개당 DALL-E 3회 호출(비용·레이턴시 3배).
- **결정/조치**: 사용자 결정 — "1회 생성 + 3회 리사이즈" 채택. 어댑터 인터페이스를 `generate(prompt) -> bytes`(마스터 이미지)로 변경, 공용 `resize_to_profile(master, profile)` 함수 분리, 파이프라인이 마스터 1장을 받아 3개 프로파일로 리사이즈. `MASTER` 프로파일(1024×1024) 상수 추가. 계획 Task 2/5/6 및 테스트 전부 반영 완료.

#### m3. 프로덕션 기본값이 회색 플레이스홀더 + `visual_ready`
- **위치**: 계획 `Task 6` `_default_image_adapter()`
- **내용**: 프로덕션에서 `FACTORY_IMAGE_GEN_PROVIDER` 미설정 시 `none` → `PlaceholderImageAdapter`(단색 회색 PNG)가 저장되고 상태가 `visual_ready`로 마킹된다. "성공"으로 보이지만 실제로는 placeholder.
- **제안**: 의도된 동작임을 계획/운영 문서에 명시하거나, `none` 프로바이더에서는 `skipped`/별도 상태를 고려.

#### m4. 기본 저장 경로 `/tmp/factory-space/assets`는 휘발성
- **위치**: 계획 `Task 6` `_DEFAULT_STORAGE_PATH`
- **내용**: `/tmp`는 재부팅·정리 시 소실. 프로덕션 자산 영속화에 부적합.
- **제안**: 기본값을 프로젝트 내 영속 경로(예: `var/assets`)로 두거나, 환경변수 필수화를 운영 문서에 명시.

### ⚪ Nit

- **n1. 슬롯 네이밍 불일치**: 기존 `VisualAssetPipeline.session_factory`는 public인데 신규 슬롯은 `_image_adapter`/`_storage_adapter`로 언더스코어. 외부(conftest)에서 직접 대입하므로 동일하게 public 네이밍이 일관적. (`db/engine.py:43`의 `get_db_session` 컨텍스트매니저 사용 패턴은 계획과 정합함 — OK)
- **n2. 함수 내부 import**: `test_adapter.py`의 `import base64`가 테스트 함수 내부에 있음. 모듈 상단으로 이동 권장.
- **n3. `NoopStorageAdapter` 단위 테스트 부재**: `storage.py`에 신설되지만 `test_storage.py`에서 직접 검증하지 않음(파이프라인에서 간접 사용). 커버리지 보강 여지.
